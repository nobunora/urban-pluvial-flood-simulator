# 1. v0.1のシステム成果

## 1.1 必須エンドツーエンド成果

一般的なWindows PCで以下を実行できること。

```text
ローカルアプリ起動
→ ブラウザでローカルUIが開く
→ 住所/地名検索または緯度経度入力
→ 矩形または±250/500/1000/2000 mを選択
→ 過去豪雨/任意降雨を選択
→ Full 1 m / Adaptiveを選択
→ 解析開始
→ 公開データ自動取得
→ SFINCSモデル自動作成
→ 互換SFINCSエンジン確認/取得
→ SFINCS実行
→ 結果正規化
→ 最大浸水深を地図表示
→ 時刻別水深・地点値を確認
```

通常フローでGIS変換やSFINCS入力編集を手作業で要求してはいけません。

## 1.2 ローカル優先

v0.1は**ブラウザUIを持つローカルアプリ**です。

```text
Browser
  │ loopback HTTP
  ▼
FastAPI
  ├─ データプロバイダ
  ├─ 前処理
  ├─ 降雨
  ├─ 格子生成
  ├─ HydroMT-SFINCSモデル準備
  ├─ SFINCS実行
  ├─ 結果正規化/描画
  └─ cache / manifest / project state
       │
       ▼
SFINCS v2.4.0 Galibier
```

ローカルサーバは既定で `127.0.0.1` のみにbindします。

ホスト型/マルチユーザーブラウザ実行はv0.1対象外です。

## 2.2 SFINCS

基準エンジン:

- **SFINCS v2.4.0 Galibier**。

実行時に`latest`追従は禁止。

managed engine manifestには正確なversion、source tag/commit、platform、binary SHA-256、license、corresponding-source URLを保存します。

## 2.3 HydroMT-SFINCS

v0.1ではモデルセットアップ層としてHydroMT-SFINCSを必須にします。理由はSFINCS upstreamが推奨し、quadtree/subgridモデル書出しを所有しているためです。

基準候補:

- `hydromt_sfincs` **2.0.0-rc3** を厳密pin。

pre-releaseのため、通常実装前にPhase 0の互換性スパイクを必須とします。

1. 小さなregular modelを作成。
2. 小さなquadtree modelを作成。
3. subgrid modelを書き出す。
4. SFINCS v2.4.0を実行。
5. HydroMTの結果readerが壊れていても、必要ならXarrayでNetCDFを直接読んで正規化できることを確認。

重大な失敗なら `spec-change-required` で停止します。v1.xへ黙ってdowngradeしたり、独自SFINCS formatを追加実装してはいけません。

# 5. ローカルサーバとprocess model

## 5.1 lifecycle

```text
application executable
→ 空きloopback port選択
→ FastAPI/Uvicornを127.0.0.1で起動
→ /api/v1/health待機
→ default browserを開く
→ 同一originでSPA/API配信
```

## 5.2 同時実行

アプリ1instanceにつきactive simulationは**1つだけ**。

2つ目の開始はHTTP `409` + `RUN_ALREADY_ACTIVE`。

## 5.3 background

長時間処理でFastAPI request threadをblockしない。1つのapplication-owned background worker/executorを使用し、Celery/Redisは追加しない。

## 5.4 cancel

1. `CANCELLING`。
2. 新stage開始停止。
3. SFINCSへgraceful terminate。
4. 最大5秒待つ。
5. 残ればkill。
6. `CANCELLED`。
7. log/manifestは残す。
8. 部分結果を完成結果として出さない。

## 5.5 local security

- same-originのみ;
- CORS default off;
- loopback bind;
- mutation endpointは`application/json`のみ;
- 不正Content-Typeは415;
- raw住所検索文字列をinfo logへ残さない;
- user errorへfilesystem pathを出さない;
- user label由来filenameをsanitize。

# 8. 雨量data/scenario

runtimeでJMAを大量scrapeしない。

release asset:



- duration minutes;
- precipitation total mm;
- date/time;

## Historical uniform


# 9. v0.1固定水理仮定

## 浸透

**OFF**。infiltration inputを生成/設定しない。

## 下水

管、inlet、manhole、pump、surchargeなし。

## Manning

```text
general n = 0.030
road    n = 0.020
```

## 外周境界

eligible boundary cellにSFINCS outflow `msk=3`。

river/tide water level forcingなし。

## 建物

建物footprintはhydraulic obstruction。

- blocked building cellをflux通過させない;
- interior storageなし;
- Adaptiveで建物越しfalse connectivityを作らない;
- dataがある建物境界は1m hydraulic resolution。

# 10. 屋根雨量の質量保存

各connected building footprintごとに:

1. 1m rain-allocation grid上のfootprint areaを求める。
2. building weightを0。
3. 非建物perimeter ground cellを探す。
4. 除去雨量volumeを配る。
5. total volumeを保存。

recipientはまず8-neighbor隣接地表。なければ1mずつChebyshev ringを広げ、最大**5m**。

5m以内にrecipientがなければ `ROOF_RUNOFF_NO_RECIPIENT` でmodel preparation失敗。volumeを捨てない。

同一建物内recipientへ面積比例で均等配分。

```text
rain_weight = 0   building
rain_weight = 1   normal ground
rain_weight > 1   roof recipient
```

fixture relative error <= `1e-9`、real model <= `1e-6`。

SFINCS forcing:

```text
P_hydraulic(x,y,t) = P_meteorological(t) × rain_weight(x,y)
```

これは屋根補正であり、気象降雨の一様仮定は維持します。

---

# 11. Full 1 m

hydraulic cell sizeはmetric projection上で**1m**。

selected rectangleをcover。内部paddingは記録し、ユーザー統計から除外。

Adaptive heuristicの影響を受けないreference mode。

大面積は自動禁止せずresource warning。実際にmemory hard constraintが判定できた場合のみblock可。

---

# 12. Adaptive

accuracy-first。

```text
1, 2, 4, 8, 16, 32 m
```

2:1 balance等SFINCS/HydroMT互換を守る。

## Hard refinement

- building footprint/intersection: 1m;
- buildingから2m以内: <=2m;
- road surface: 1m;
- roadから2m以内: <=2m;
- narrow channel / concentrated flow path: <=2m。

## Terrain complexity

raw slopeのみで判断しない。smooth mountain slopeはcoarse可。

best-fit planeから:

- residual RMSE;
- max abs residual;
- curvature;
- connectivity-changing depression/ridge;
- flow accumulation concentration。

初期暫定threshold:

| Target | RMSE | max abs residual |
|---:|---:|---:|
| 32 m | <=0.08 m | <=0.25 m |
| 16 m | <=0.06 m | <=0.20 m |
| 8 m  | <=0.05 m | <=0.15 m |
| 4 m  | <=0.04 m | <=0.12 m |
| 2 m  | <=0.03 m | <=0.10 m |
| 1 m  | otherwise | otherwise |

hard featureがある場合は粗化不可。

## Subgrid

coarse cellでも最良高解像度terrainをHydroMT-SFINCS subgrid生成へ使う。先にDEM全体をcoarse resolutionへ平均してはいけません。

## Diagnostics

- level別cell count;
- total cells;
- full equivalent;
- reduction ratio;
- refinement reason;
- UI grid-resolution layer;
- threshold config identity。

# 20. テスト契約

## Python unit

GSI decode、orientation、PLATEAU axis、OSM fallback、rain conversion、roof mass、Adaptive plane/hard refine、2:1 balance、run state、cache、manifest、error、point lookup、render dry/no-data。

## network integration

release前にlive GSI/PLATEAU/OSM/geocoder/JMA maintenance path。

## SFINCS smoke

1. flat + no rain → zero。
2. bowl + constant rain → nonzero、no NaN/Inf。
3. building + roof redistribution → mass conserve、blocked。
4. regular 1m。
5. quadtree/subgrid。

## Adaptive acceptance

- depth>=0.05m flooded-area IoU **>=0.90**;
- mutually wet median abs max-depth diff **<=0.03m**;
- p95 **<=0.10m**;
- final water volume relative diff **<=2%**（open outflow考慮）;
- 重要road/channel connectivity class変化なし;
- open-area benchmarkでcell数削減。

failならAdaptiveはdeveloper/experimentalのまま。推奨表示禁止。
