# Result viewport cache: implementation specification

> Status: implementation contract. Canonical language: English.
>
> Companion: `v0.1-result-viewport-cache-spec.md`.

## 1. Required outcome

For new uniform Full 1 m, 2 m and 4 m runs, a successful SFINCS process MUST
become COMPLETE without creating a dense `time x row x column` NumPy array or
`normalized_full_1m.npz`. The result viewer MUST preserve current map layers,
native one-minute values, vectors, point inspection, Japanese labels, and
existing schema-1 NPZ/Adaptive compatibility.

## 2. Confirmed impact map

| Area | Existing file and assumption | Required work |
| --- | --- | --- |
| Regular reader | `floodsim/sfincs/output_reader.py:read_regular_result` loads whole h/u/v | Add metadata-only `inspect_regular_result`; keep dense reader for legacy only |
| Completion | `floodsim/orchestration/run_coordinator.py` calls reader then `normalize_regular_result` | Use bounded finalizer and descriptor for regular results |
| Persistence | `floodsim/results/normalize.py` writes NPZ | Write metadata plus source descriptor atomically |
| Viewer | `floodsim/results/view.py` assumes `NormalizedArrays` | Add source operations; retain NPZ and Adaptive branches |
| Vectors | `floodsim/results/vector_viewport.py` indexes complete arrays | Read h/u/v only for viewport chunks |
| Routes | `floodsim/api/routes_results.py` LRU-caches complete arrays | Cache source objects and byte-accounted chunks |
| Browser | `web/src/api/client.ts`, `ResultPanel.tsx`, `ResultMap.tsx` sends bounds only for vectors | Send bounds for depth; add cancellation/debounce/prefetch |
| Archives | `floodsim/results/archive.py` requires exactly one NPZ | Add schema 2 descriptor+NetCDF; keep schema 1 import |

Do not implement only the completion change. It would make the current viewer,
archive path, and browser URL contract unable to open the new result.

## 3. Persisted source descriptor

Create `results/regular_netcdf_source.json`, schema
`regular-netcdf-source-v1`, containing: relative `sfincs_map.nc` filename,
source size and mtime, grid height/width, uniform block size, bounds, time
values, variable names (`h`, `hmax`, `zb`, `msk`, optional paired `u/v`), chunk
shape, vector availability, and cache schema revision. It MUST NOT contain a
numeric time-by-grid array or an absolute path.

Resolve the source only beneath the run `model/` directory. Reject descriptor
path escape, source identity mismatch, missing variable, dimension mismatch,
or unpaired u/v. Add `output_files.result_source`; do not put JSON into
`normalized_arrays`. `result_metadata.json` retains its public schema and may
add `storage_kind`, chunk shape, and cache diagnostics.

## 4. Finalizer and legacy recovery

After SFINCS success:

1. inspect variable names, dimensions, coordinates, and NetCDF encoding;
2. scan terrain/mask/hmax one source chunk at a time for current diagnostics;
3. reconstruct any hmax diagnostic using one time/chunk at a time;
4. atomically write metadata and descriptor;
5. update manifest, then transition COMPLETE.

Never call full-variable `.values` for h/u/v, create 3-D boolean arrays, or
write dense NPZ. A solver-complete legacy run stuck at `READING_RESULTS` runs
these steps from its retained NetCDF without launching SFINCS. After COMPLETE,
render/prefetch failure is `RESULT_VIEW_*`, never a run failure.

## 5. Source interface and reads

Create `floodsim/results/regular_netcdf_source.py`. It owns descriptor
validation, NetCDF access, cache, and these operations:

```text
render_depth(bounds, time_index, max_px) -> PNG
render_max_depth(bounds, max_px) -> PNG
render_grid_resolution(bounds, max_px) -> PNG
read_vectors(bounds, time_index, spacing_m) -> GeoJSON
inspect_point(row, column, optional_time_index) -> mapping
```

Convert WGS84 viewport to local coordinates once, clamp grid limits, and find
chunk IDs with integer division by chunk height/width. Do not create a regular
grid R-tree or quadtree: a uniform rectangle has O(1) row/column/chunk lookup.
Open datasets per operation or with a verified thread-safe bounded pool; never
share a backend handle across threads by assumption.

PNG rendering reads one intersecting chunk/time at a time, applies the existing
dry/no-data policy and palette, and composites directly to the requested pixel
rectangle. Zoomed-out requests may sample for image pixels only. Vector reads
selected h/u/v chunks then applies existing physical-spacing sampling. Point
inspection reads mask/terrain/hmax at one cell and the h time series in bounded
time slices; it must return each native minute exactly.

Vector display density is defined by grid-aligned physical-spacing bins. Each
visible bin selects the finite wet cell (or adaptive face) nearest the bin
centre rather than sampling only the bin anchor or selecting the fastest cell.
This distributes arrows evenly while ensuring that a dry or missing anchor
cannot hide flow elsewhere in the bin. Browser target spacing starts at 6 m at
zoom 18 and doubles for each zoom-out level, capped at 4096 m. Result maps
allow overzooming to zoom 21, where the request stride reaches one and exposes
the highest available vector and particle density. The vector
control remains disabled until the map reports its current viewport and zoom,
so enabling vectors cannot briefly request maximum-density data for a stale
initial zoom. The initial viewport report occurs after MapLibre construction and
does not wait for external raster tiles to finish loading; later move/zoom events
replace it with the latest bounds before the next vector request.

The result UI exposes terrain elevation next to the calculation-grid layer.
Elevation uses exactly eight stepped rainbow bands spanning the minimum and
maximum finite elevation of active cells in that analysis result. The numeric
band limits are persisted in result metadata; compatible older archives derive
the same limits when loaded. Elevation legend values allow negative metres so
coastal and below-sea-level terrain remains valid. This deliberately prioritizes local relief over
absolute color comparability between different runs.

Both the GSI standard basemap and result overlays are raster images. The GSI
source keeps its native maximum at zoom 18, while result-map interaction allows
MapLibre overzooming through zoom 21 so users can reach stride-one flow data.
The three overzoom levels intentionally trade raster sharpness for inspection
of the highest-density vector and particle field; no nonexistent GSI zoom-19+
tiles are requested.

The production web build must emit MapLibre's module worker as a versioned Vite
asset and configure MapLibre with that emitted URL. A missing worker is a failed
map initialization, not a condition in which vector controls may be enabled.

Grade-separated transport structures are an explicit v0.1 limitation: flow
under overpasses, through tunnels, or beneath elevated expressways is not
modelled. The current road-provider boundary retains geometry but not reliable
bridge, tunnel, or vertical-layer semantics, so no speculative terrain or
hydraulic correction is applied until those attributes have an end-to-end
validated contract.

The setup UI distinguishes sample conditions from persisted results by
responsibility: selecting a ranked sample only fills a new-analysis condition,
while opening an analyzed sample or imported archive is a result-loading action.
Result headings and other provenance must come from the loaded result metadata,
never from the current setup form state. A built-in analyzed sample belongs to
the analyzed-results group and should carry a sample badge rather than being
mixed into the condition selector.

The setup screen preserves the compact historical sample list. Selecting one
sample opens a modal choice instead of adding separate sample-condition and
analyzed-result lists to the setup card:

- `解析条件に反映` copies the sample rainfall, location and recommended extent
  into the editable new-analysis form. The user may then change the location
  while retaining the sample rainfall condition.
- `解析済みデータを読み込む` opens the persisted result when that sample
  archive exists. The action is disabled with an availability note when the
  archive is not configured.
- `ファイルから読込` remains above the compact sample list for importing a
  user-created result ZIP in local mode.

The setup action row also includes `標高のみ取得` beside `解析開始`. This is a
dedicated, non-run preview operation: it fetches GSI elevation for the exact
current analysis bounds and grid size, renders the same eight-band local Min-Max
palette, and does not acquire vectors/rainfall, build a model, start SFINCS, or
create a completed hydraulic result. Preview images are held in a bounded
process-local byte cache and may be discarded on restart. Changing location,
extent, or grid size invalidates the visible preview. The setup remains editable
and offers `この条件で解析開始` after inspection.

`2. 実行状態` updates a broad `概算ピークメモリ` range whenever the extent or
minimum block size changes. The v0.1 estimator uses the displayed uniform cell
count and reports `(0.5 GiB + 512 bytes/cell)` through
`(1.0 GiB + 1024 bytes/cell)`. This range intentionally includes Python
preprocessing arrays, temporary conversion copies and the SFINCS working set;
it is guidance rather than an allocation guarantee. The UI states that feature
count and the execution environment can move the observed peak outside the
range.

The Full-grid roof-runoff preprocessing must intersect provider building
polygons with the active land/DEM domain before connected-component labelling
and recipient search. Provider polygons over sea or DEM-uncovered cells receive
no meteorological rainfall and are not roof cells for mass accounting. This
preserves the existing 5 m recipient limit and `ROOF_RUNOFF_NO_RECIPIENT`
failure contract for real active-domain roofs, while preventing false failures
from out-of-domain provider geometry.

Flow particles reuse the viewport vector response; they do not introduce a
second numerical flow field. `流れベクトル` and `粒子フロー` are mutually
exclusive neighboring controls. Particle rendering uses a single transparent
Canvas overlay and two reusable particles per sampled flow feature. Thus the
steady and initial visible particle count is twice the vector-arrow count at
every zoom level, including low zoom. The client
constructs a screen-space vector field from the viewport response and uses
distance-weighted interpolation of nearby vectors to update each particle's
direction and speed every frame. A particle is not tied to its seed arrow: its
normal lifetime covers at least fifteen representative vector spacings before it
is reseeded. Leaving the viewport or reaching a disconnected part of the field
may reseed it early. Screen travel remains monotonic with `speed_mps`. The
particles are divided deterministically into four lifetime-phase groups. All
particles are visible immediately; the phase is represented by initial travelled
distance rather than a hidden activation delay. This keeps the visible density
at two particles per vector while spreading their first reseed times. Extending
the lifetime to fifteen spacings lets multiple generations overlap. Each particle retains
its source-vector assignment across reseeding; only its deterministic offset
changes. This prevents short-lived fast particles from migrating into and
accumulating within longer-lived slow regions. Normal reseeding is drawn in the
same frame so a lifetime or viewport reset never creates a speed-dependent
blank frame. Thus approximately one quarter,
which is within the requested one-third to one-fifth range, enters the field at
each phase. The particle head is a
zero-length point. Its actual curved history is retained as
a 75 px trailing path (three times the prior 25 px path) and fades
continuously from transparent at the tail to the flow color at the head. Map
movement, time changes
and viewport-density changes rebuild the particle seeds without creating DOM
nodes per frame. Animation stops and clears its frame callback immediately when
the layer is hidden or the component unmounts.

Particle screen travel is proportional to the locally interpolated hydraulic
speed: `36 px/s` per `1 m/s`, clamped only to `1.5..96 px/s` so nearly stagnant
particles remain visible and extreme values cannot jump across the viewport in
one frame. No constant base speed is added; therefore 0.5, 1.0 and 2.0 m/s are
visibly represented as 18, 36 and 72 px/s respectively.

### 12.3 Public Windows bundle and demo case contract

The public Windows bundle keeps the application in local mode. When sibling
`demo-results` and `sfincs` directories exist beside the frozen executable,
the launcher configures them automatically; `--demo-results-dir` and
`--sfincs-bin` may override those locations.

The bundled SFINCS executable MUST be built from the public Deltares/SFINCS
GPL-3.0 source at the pinned v2.4.0 Galibier tag, not copied from the separately
licensed Deltares precompiled download. Its complete dependent runtime DLL set,
GPL license, upstream README and exact corresponding source archive are shipped
beside it. Acceptance requires the extracted distribution to start and finish
a solver smoke run on a Windows host without Python, a separate SFINCS install,
or changes to the system PATH.

The published demo set uses the existing calculated Yokkaichi and Chiba
archives. Yokkaichi covers a 2000 m half-width and Chiba retains its existing
1000 m half-width. Saga and both Nagoya cases are generated at a 500 m
half-width on a uniform 1 m grid. All five public cases expose exactly the 0,
15, 30, 45 and 60 minute frames. The demo manifest records each event's actual
half-width, archive byte size and SHA-256 digest; mixed extents must not be
described by one global extent field.

Regular-grid demo generation exports archive schema 2 with the immutable
`sfincs_map.nc` source and its source descriptor. The generator must not assume
that every completed result has the legacy `normalized_arrays.npz` output;
schema 1 remains only for Adaptive or compatible imported results.

In the compact condition grid, every input and select uses the width of its
grid cell. In particular, longitude and duration must render at the same width
as extent and minimum block size before the public build is accepted.

## 6. Cache and browser scheduler

Key cache entries by `(run_id, source identity, cache revision, variable,
time, chunk row, chunk column, representation)`. Account decoded, rendered,
and in-flight bytes. On every admission/eviction:

```text
headroom = max(2 GiB, 20% total physical RAM)
budget = min(4 GiB, 35% max(0, available RAM - headroom))
```

At a zero budget, stream one chunk then release it. Evict stale generation,
outside one-ring, distant time, then LRU. Pin only selected visible chunks
while composing their response.

Add viewport bounds to depth-image requests. Keep the old no-bounds endpoint
temporarily for legacy callers, with strict output pixel cap; new browser code
must not use it. A monotonically increasing generation is created on pan/time
change. Priority: visible selected time immediately; surrounding selected-time
chunks after 1000 ms idle, pan direction first; previous minutes nearest first
after 2000 ms idle. New work aborts browser fetches and invalidates older queued
work, but never cancels SFINCS.

## 7. Archive migration

Schema 1 remains the exact NPZ-only archive and existing import path. Schema 2
contains config, manifest, metadata, descriptor, and NetCDF at fixed relative
names. Export selects schema by storage kind. Import dispatches by archive
schema and validates member allowlist, size, path containment, descriptor, and
source identity. Demo schema-1 archives and Adaptive output must keep working.

## 8. Ordered, non-skippable delivery plan

1. Descriptor/inspector/finalizer unit tests; no route changes.
2. Source reader tests: chunk selection, native minute values, bounded memory,
   zero-cache streaming, eviction order.
3. Coordinator completion and legacy recovery.
4. Source-backed route branches for map, vectors, inspection; preserve all
   response schemas and legacy branches.
5. Browser bounded-image URL, generation cancellation, debounce and status.
6. Schema-2 export/import; rerun schema-1 and Adaptive tests.
7. Local browser review; then ±2000 m 1 minute, 2 minutes, 10 minutes; only
   then consider ±4000 m.

On any failed step, repair and rerun that step. Do not start a longer SFINCS
evaluation before completion and display acceptance for the preceding step.

## 9. Responsibility-boundary controls

The following boundaries were re-checked against the current source. Each is a
required implementation/test boundary; do not merge responsibilities merely to
make the first source-backed path work.

| Boundary | Current risk | Required owner and control |
| --- | --- | --- |
| Solver output -> result finalizer | `READING_RESULTS` currently fails the run after solver success | Coordinator owns lifecycle; finalizer owns bounded validation only. Persist descriptor/metadata before manifest COMPLETE and preserve raw NetCDF on every finalizer failure. |
| Manifest -> filesystem artefacts | Startup currently restores COMPLETE from metadata presence | Artifact resolver owns validation of descriptor plus NetCDF identity before exposing a result. Missing/corrupt source yields `RESULT_NOT_READY`/view error, never a false usable COMPLETE response. |
| Immutable source -> evictable cache | Existing LRU caches complete arrays with only file mtime input | Source object owns identity validation; cache owns only derived bytes. Never delete, rewrite, or mutate NetCDF during cache eviction. Include source identity and schema revision in each key. |
| Cache policy -> operating system memory | Process cache can pressure unrelated solver/UI work | Cache manager alone samples memory and admits/evicts bytes. Renderer must function when its admission is denied; no caller may retain an unaccounted decoded chunk. |
| Browser abort -> server work | `AbortController` stops client interest but does not guarantee backend cancellation | Browser owns fetch abort; server scheduler owns generation cancellation. Check generation before disk I/O and cache insertion; a disconnected request must not publish stale prefetch. |
| Browser viewport -> image API | Current depth URL omits bounds, while vectors include them | API schema owns validated bounds/max pixel values; client owns normalized bounds and monotonically increasing request generation. Do not infer bounds from browser state on the server. |
| Public HTTP -> browser cache | Layer routes declare one-year immutable caching | Every rendered-image cache key/URL must include run id, source identity or immutable run result, layer, time, bounds, pixel size, and rendering revision. Do not reuse an old whole-run URL for viewport images. |
| Renderer -> numeric inspection | Image sampling can accidentally be reused as data | Renderer may downsample only RGBA pixels. Point/vector methods always read native numeric samples independently. |
| Uniform regular -> Adaptive topology | Regular integer chunk lookup is invalid for faces | Dispatch by persisted storage kind before any geometry indexing. Adaptive keeps current face/layout readers and tests unchanged. |
| Export/import -> path safety | Schema-1 archive is an exact member allowlist | Archive module owns schema dispatch and extraction validation. Schema-2 validates names before extraction, uses fixed destinations, rejects duplicates/extra members, and resolves descriptor source only within the imported run. |
| Run cancellation -> result viewing | Run cancellation currently targets pre-COMPLETE work | Never connect viewport cancellation to `RunCoordinator.cancel`. Completed results remain readable; only viewer queue items are cancelled. |
| Threads -> NetCDF handle | Coordinator has worker threads and current route caches are process-global | Source factory owns handle lifetime and synchronization. Use per-operation handles initially; add a pool only with concurrency tests. Cache locks must not be held during NetCDF I/O or PNG encoding. |

### 9.1 Commit/restore transaction

The finalizer commit order is mandatory: atomically write metadata and
descriptor; verify both by reopening them; atomically write manifest with
`result_source`; only then transition the in-memory state to COMPLETE and emit
the completion event. If interrupted before the manifest write, recovery may
finalize again. If interrupted after it, startup validates source identity;
it must not merely trust metadata JSON.

### 9.2 Error ownership

Input/descriptor/archive violations map to deterministic contract errors.
NetCDF I/O and rendering failures map to `RESULT_VIEW_*`; they leave a
solver-complete run COMPLETE but return an actionable display error. Memory
admission failure selects streaming, not an error. Only failure before SFINCS
completion may produce a calculation FAILED state. Each mapping needs a route
test and a browser-visible Japanese message where the user can act on it.

## 10. Mandatory acceptance tests

- 21-time chunked synthetic NetCDF finalizes without a full 3-D read.
- 8000x8000 retained result finalizes with descriptor only.
- ±2000 m 1-minute run completes and locally renders depth/max/grid/vectors;
  point inspection returns all native minutes.
- Low-memory simulation streams correctly and never changes COMPLETE to FAILED.
- New pan/time cancels stale work; 1 s/2 s queues have required order.
- 1/2/4 m vector apparent spacing remains comparable.
- Schema-1 import/export, demo, and Adaptive tests stay green.
- Schema-2 rejects missing NetCDF, extra members, escaped paths, and identity
  mismatches.

## 11. Explicit non-solutions

Do not lower the output interval, create a mandatory full PNG/Zarr pyramid,
add a regular-grid tree, or treat cache pressure as a hydraulic failure.

## 12. Implementation detail log

### 12.1 Result metadata response compatibility

`ResultMetadataResponse` must retain `extra="forbid"` and explicitly declare
optional `storage_kind`, `chunk_shape`, and `cache_schema_revision`. This keeps
the pre-existing response contract strict while allowing the additive metadata
fields permitted by section 3. The fields remain absent for schema-1 NPZ and
Adaptive results; clients must not treat their absence as an error.

### 12.2 Published Yokkaichi demo cadence

The bundled Yokkaichi analyzed result is a distribution artifact rather than
the native working result described in sections 1 and 4. Before publishing its
schema-2 ZIP, post-processing MUST retain exactly the elapsed 0, 15, 30, 45 and
60 minute frames in `sfincs_map.nc`; `h`, paired `u/v`, and every other variable
using the `time` dimension are reduced together, while static variables and
`timemax`/`hmax` remain unchanged. The rewrite MUST copy bounded NetCDF chunks
to a sibling temporary file, validate the resulting time dimension, and replace
the source atomically. It MUST NOT load a complete time-by-grid variable.

After replacement, the regular source descriptor and result metadata are
regenerated before schema-2 export so source size/mtime identity and the public
`available_time_indices`/`time_values` contract describe the five retained
frames. Import acceptance requires a self-contained descriptor+NetCDF archive,
five displayed times, and successful depth/vector rendering. Schema-1 NPZ
archives remain unchanged.

### 12.3 Source-backed point inspection time semantics

Point inspection for a regular NetCDF-backed result MUST read the complete
retained depth series for only the selected native cell when determining
`max_time_index` and `max_time_value`. A single selected display frame MUST NOT
be treated as the complete series. Changing the displayed time after a point
has been selected MUST re-run native inspection for the same coordinates so
`depth_m` and `time_value` describe the displayed frame. Numeric NetCDF time
strings are elapsed seconds and MUST be formatted as elapsed time before any
date parser is considered.
