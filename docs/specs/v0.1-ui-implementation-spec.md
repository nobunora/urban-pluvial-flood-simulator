# 3. OpenAPI type generation

Backend OpenAPI is authoritative for API DTO structure.

Required flow:

```text
FastAPI openapi.json
→ openapi-typescript
→ web/src/api/generated.ts
```

Repository SHALL provide deterministic command:

```bash
npm run api:generate
```

and drift check:

```bash
npm run api:check
```

`api:check` regenerates to temporary output and fails if committed generated types differ.

Frontend MUST NOT manually redefine API request/response interfaces already present in generated OpenAPI types.

Frontend domain types MAY wrap generated DTOs when the UI needs a stronger local discriminated union, but conversion must occur in one named adapter function with tests.

# 4. State architecture

Use React `useReducer` + Context for application-level state.

Do not use scattered top-level `useState` flags for workflow state.

## 4.1 App state shape

Conceptual exact shape:

```ts
type AppMode = 'SETUP' | 'RESULT';

type AppState = {
  mode: AppMode;
  backend: BackendState;
  setup: SetupState;
  run: RunLifecycle;
  result: ResultState | null;
  ui: UiTransientState;
};
```

## 4.2 Setup state

```ts
type SetupState = {
  location: LocationSelection;
  area: AreaSelection | null;
  rainfall: RainfallSelection;
  accuracy: 'full_1m' | 'adaptive';
  estimate: ResourceEstimateState;
};
```

`canStartRun` MUST be derived in selector. Never persist `canStartRun` boolean.

## 4.3 Run lifecycle discriminated union

```ts
type RunLifecycle =
  | { kind: 'IDLE' }
  | { kind: 'SUBMITTING' }
  | { kind: 'ACTIVE'; runId: string; snapshot: RunSnapshot; lastSequence: number }
  | { kind: 'CANCELLING'; runId: string }
  | { kind: 'COMPLETE'; runId: string }
  | { kind: 'FAILED'; runId?: string; error: UiError }
  | { kind: 'CANCELLED'; runId: string };
```

Do not duplicate backend stage state into additional booleans such as `isDownloading`, `isRunningSfincs`, etc.

## 4.4 Result state

```ts
type ResultLayer = 'max_depth' | 'time_depth' | 'grid_resolution';
type DepthColorMode = 'bands' | 'rainbow';

type ResultState = {
  metadata: ResultMetadata;
  layer: ResultLayer;
  colorMode: DepthColorMode;
  timeIndex: number | null;
  inspectedPoint: PointInspectionState;
};
```

Timeline current time is derived from `metadata.times[timeIndex]`.

## 4.5 Action rule

Every reducer action name describes a domain event, e.g.:

```text
LOCATION_SELECTED
AREA_PRESET_SELECTED
AREA_RECTANGLE_COMMITTED
RAINFALL_SCENARIO_SELECTED
ACCURACY_SELECTED
RUN_CREATED
RUN_EVENT_RECEIVED
RUN_FAILED
RESULT_METADATA_LOADED
RESULT_LAYER_SELECTED
POINT_INSPECTION_LOADED
```

Avoid generic `SET_DATA`, `UPDATE`, `HANDLE_CHANGE` for application state transitions.

# 5. State invariants and reducer tests

Reducer MUST enforce or selectors MUST derive these invariants:

1. `mode === RESULT` implies completed run and loaded result metadata.
2. `adaptive` may be selected only when backend capability says available; experimental availability may still be selectable if product config allows it.
3. area preset requires location center.
4. rectangle area does not require location search result.
5. historical station query center for rectangle-only setup is rectangle centroid.
6. run submission uses same area/rainfall/accuracy objects shown in summary.
7. while active run exists, setup mutation actions are ignored or UI-disabled; reducer tests cover behavior.
8. stale SSE sequence numbers are ignored.
9. terminal run event closes SSE.
10. new analysis preserves previous setup but clears active result view state.

Each invariant requires a focused unit test.

# 6. HTTP client

Create one API client module.

Responsibilities:

- base URL = same origin;
- JSON request/response;
- content type validation;
- convert backend stable error body to `UiError`;
- abort support with `AbortController`;
- no retry by default at generic client level.

Provider/run-specific retries belong to backend.

Frontend MAY retry idempotent UI fetches such as resource estimate once after transient network disconnect, but do not hide persistent errors.

Do not log full address query or response body to browser console in production builds.

---

# 7. SSE client

`web/src/api/sse.ts` owns EventSource lifecycle.

Rules:

- one EventSource per active run;
- close previous source before opening a new one;
- ignore duplicate/out-of-order `sequence <= lastSequence`;
- on temporary SSE transport error, query `GET /runs/{id}` once to reconcile state before deciding failure;
- terminal run state closes stream;
- component unmount closes stream;
- no multiple reconnect loops implemented independently by components.

SSE event parsing is schema-checked at runtime with explicit guards; malformed event triggers UI error code `UI_BAD_RUN_EVENT` and reconciliation request.

# 8. Map implementation

Use MapLibre GL JS.

## 8.1 Base map

Default background is GSI standard raster tiles using MapLibre raster source/layer.

Base tile template:

```text
https://cyberjapandata.gsi.go.jp/xyz/std/{z}/{x}/{y}.png
```

Attribution shown in map attribution control:

```text
国土地理院
```

Do not hide required source attribution.

## 8.2 Coordinate order

MapLibre uses `[longitude, latitude]`.

Create helper with explicit name:

```ts
toLngLatTuple(point: LonLat): [number, number]
```

Do not pass raw `[number, number]` tuples between domain state and map code without this adapter.

## 8.3 Center marker

Use one marker instance.

Marker updates from location state. Map clicks in setup may dispatch `LOCATION_MAP_POINT_SELECTED` when not in rectangle drawing mode.

## 8.4 Analysis area source

Use one GeoJSON source for selected analysis rectangle.

Style:

- visible outline;
- translucent fill;
- high contrast against GSI standard map.

Map geometry is rendering of state, not the state source itself.

# 9. Rectangle drawing implementation

Do not add a drawing framework dependency for one rectangle tool.

Implement dedicated drag interaction in `areaDrawing.ts`.

## 9.1 Interaction

When rectangle mode enabled:

1. set cursor crosshair;
2. on primary pointer down over map, store start lon/lat and disable map pan temporarily;
3. on pointer move, update preview bounds;
4. on pointer up, normalize west/east/south/north;
5. reject negligible drag;
6. calculate width/height/area using backend-compatible geodesic/projected helper;
7. dispatch committed rectangle;
8. re-enable map pan.

Escape during active drag cancels preview and restores pan.

Component unmount/error MUST restore map interactions.

## 9.2 No DOM pixel area calculation

Area/width must not be derived from screen pixels.

Use geographic coordinates and a tested metric calculation. Backend remains authoritative; frontend estimate may be replaced by backend normalized area after estimate response.

## 9.3 Tests

Unit-test pure bounds normalization and cancel behavior. Playwright tests actual drag using fixed map mock/coordinates where deterministic.

# 10. Component contracts

## 10.1 `LocationStep`

Receives:

- location state;
- search state;
- callbacks only.

Owns local search input text only. Selected canonical location is application state.

Search behavior:

- Enter submits;
- blank disabled;
- cancel prior search request when a new search begins;
- result list keyboard accessible;
- search provider attribution shown.

## 10.2 `AreaStep`

Receives selected area/location and dispatches mode/preset/draw actions.

No API calls directly except optional estimate trigger through parent/controller hook.

## 10.3 `RainfallStep`

Subcomponents MAY include `HistoricalRainfallPicker` and `CustomRainfallForm`.

Custom form local text is parsed only on valid numeric input; canonical rainfall state stores numeric values or explicit incomplete state.

Do not coerce empty string to zero.

## 10.4 `AccuracyStep`

Cards use real radio semantics.

Backend capability controls:

```ts
adaptive: {
  available: boolean;
  status: 'experimental' | 'recommended' | 'unavailable';
  reason?: string;
}
```

If unavailable, card disabled and reason shown.

## 10.5 `RunSummary`

Pure display component based on selectors.

No independent formatting/calculation of submitted values beyond formatting helpers shared with selection components.

## 10.6 `RunProgress`

Renders backend run snapshot.

No parsing of SFINCS logs in frontend.

## 10.7 `ResultPanel`

Owns result presentation controls only. It cannot change run config.

# 12. Resource estimate behavior

Estimate request is debounced **300 ms** after relevant setup changes and only sent when area + accuracy are valid.

Rules:

- cancel stale request;
- latest response wins;
- estimate failure does not invalidate otherwise valid setup; show `推定できませんでした` and allow run unless backend run validation later rejects it;
- do not issue estimate on every map pointer move while rectangle is being dragged — only after rectangle commit.

No wall-clock ETA display.

---

# 13. Historical rainfall UI data flow

When location/rectangle center changes:

1. clear station list selection only if previous station is no longer explicitly user-pinned; v0.1 simplest rule: always refresh nearest stations and select nearest first;
2. fetch nearest stations after 300 ms debounce;
3. selecting station fetches extremes;
4. selecting event stores event ID and mode;
5. if event changes, reset observed-profile selection to uniform unless profile is available and user selects it again.

Do not keep a profile mode selected for an event that lacks a profile.

Network errors:

- station/extreme error shown inside historical tab;
- custom rainfall tab remains usable.

Frontend validation mirrors backend ranges but backend remains authoritative.

## Custom rain

Intensity:

```text
> 0 and <= 500 mm/h
```

Duration:

```text
integer minutes, 1..10080
```

UI error appears after blur or attempted run, not on first empty render.

No silent clamp.

## Coordinates

Lat/lon ranges as UI behavior spec.

## Search

Max 200 Unicode code points before request. Over-limit error is local and prevents request.

# 15. Submission and final review

`解析開始` click does not directly POST run.

Flow:

```text
click
→ open ReviewRunModal with immutable snapshot
→ user confirms
→ POST /api/v1/runs using exactly snapshot values
```

If user edits setup after modal opens through any unexpected path, confirmation still uses modal snapshot and UI MUST show the snapshot. Preferred implementation disables underlying interaction while modal open.

After successful POST:

- store run ID;
- open SSE;
- switch left panel to progress.

If POST fails, remain SETUP with error and preserved configuration.

---

# 16. Run progress details

Maintain mapping object from backend stage enum to Japanese labels from UI behavior spec.

Mapping must be exhaustive at compile time, e.g. TypeScript `satisfies Record<RunStage, string>`.

If backend adds unknown stage and generated enum changes, TypeScript build fails until UI is intentionally updated.

Progress bar:

- determinate only when `progress_fraction` number exists;
- otherwise indeterminate CSS animation;
- percentage text only for determinate.

Elapsed time is derived from frontend monotonic clock since run creation snapshot; it is informational only.

---

# 17. Cancellation data flow

Cancel modal confirmation:

1. dispatch CANCELLING UI state;
2. POST cancel;
3. wait for backend terminal event/snapshot;
4. on network failure, reconcile with GET run;
5. do not assume cancelled solely because cancel POST returned 202/200.

When backend reaches `CANCELLED`, return user to editable setup with non-error notice:

```text
解析を中止しました。
```

Do not enter RESULT.

# 18. Result image overlay implementation

Backend provides geographic bounds in result metadata and PNG endpoint.

Use MapLibre `image` source or equivalent raster source that places one image over exact four corners.

## 18.1 Cache-busting

Layer URL includes run ID, layer, time index, color mode if backend renders colors, and application/result revision parameter as needed.

Do not append random timestamp on every render; browser caching should work.

## 18.2 Image loading state

When switching layer/time:

- keep current layer until replacement image loaded, or show clear loading overlay;
- do not blank map without status;
- discard stale image completion if user already selected another time.

## 18.3 Depth color ownership

Preferred v0.1: backend renders colorized PNG according to requested color mode and exposes legend metadata, to keep numerical palette logic centralized and reproducible.

If backend contract instead returns normalized scalar image later, spec revision required. Do not implement a competing frontend-only depth classification.

Grid-resolution categorical palette may be frontend-fixed only if metadata levels remain exact 1/2/4/8/16/32.

# 19. Point inspection implementation

On result map click:

1. cancel previous inspection request;
2. show small loading state in inspector;
3. GET inspect with lon/lat/current time index when relevant;
4. render exact backend values;
5. preserve clicked coordinate marker.

Do not derive water depth by sampling displayed PNG.

Inspection response `has_data=false` displays no-data message, not 0.

Rapid clicks: latest request wins via AbortController/request ID.

---

# 20. Timeline implementation

Timeline source is `result.metadata.times`.

`timeIndex` must always be integer index into this array or null when non-time layer.

Slider:

```text
min=0
max=times.length-1
step=1
```

Display formatter converts elapsed simulation time to `HH:MM` or `DD日 HH:MM` for >24 h.

No interpolation between indices.

Arrow controls clamp to valid range.

Changing away from time layer retains last selected `timeIndex` so return to time layer restores it, unless result changes.

---

# 21. Result metadata and limitations sourcing

Limitations in RESULT MUST come from backend metadata.

Frontend maintains a presentation mapping from machine flags to Japanese text, but if backend marks a previously false limitation as true/implemented, frontend must not still claim it is omitted.

Implementation strategy:

- backend returns structured `limitations` object;
- frontend formatter renders current facts;
- unknown new limitation keys are shown in diagnostic metadata and trigger dev warning/test failure if required by generated schema.

Provider/version metadata is display-only and never edited by user.

# 24. Accessibility implementation details

Use semantic HTML before ARIA.

Required:

- `<label>` connected with every input;
- fieldset/legend for radio groups;
- button elements for actions, not clickable divs;
- `aria-live="polite"` for stage/status updates;
- `aria-live="assertive"` only for blocking failure;
- visible focus outline via token;
- modal focus trap;
- candidate list keyboard navigation with ArrowUp/ArrowDown/Enter/Escape or standard listbox behavior;
- map canvas has accessible name; essential operations have non-map alternative where required.

Playwright accessibility smoke may use axe if dependency is approved; if axe is not added, deterministic keyboard tests plus manual checklist are mandatory. Do not add dependency solely to claim coverage without acting on findings.

# 30. Startup/health UI

Initial frontend bootstrap:

1. render shell;
2. GET `/api/v1/health`;
3. if healthy, load capability/app info;
4. enable setup;
5. if failed, show backend unavailable full-page state and retry button.

# 31. Performance rules

- map instance created once per app lifetime, not recreated on each form change;
- result PNG object/source updated, not full map reconstructed;
- debounce geocoder only on explicit submit — no typeahead network search required;
- debounce resource estimate and station lookup as specified;
- large result images loaded lazily by selected layer/time;
- do not preload every time-slice PNG;
- abort stale fetches;
- do not store PNG blobs for all frames in React state;
- use object URLs only when required and revoke them.

Frontend must remain responsive during backend simulation because heavy work is server process/thread side.

# 32. Privacy and logging

Frontend MUST NOT persist address search text in localStorage.

v0.1 MAY keep current setup in React memory and backend project/run JSON when run starts.

Do not send analytics/telemetry in v0.1.

Do not include third-party tracking scripts.

CSIS attribution/terms link is shown when that provider is configured; search queries are sent to backend, which contacts provider. Frontend does not contact CSIS directly, keeping provider logic centralized.
