# 0. UIの絶対ルール

UIは必ず:

- GIS・水理知識なしで理解できる;
- 主な4判断 **場所 / 範囲 / 雨 / 精度** を明示する;
- 重要な非考慮事項を常時確認可能にする;
- 過去豪雨scenarioを未来予報として見せない;
- provider fallbackや欠損qualityを隠さない;
- solver進捗%を捏造しない;
- Full 1mをAdaptiveへ黙って変更しない;
- 雨量mode/durationを黙って変更しない;
- 前提未成立のcontrolをenableしない。

通常UIにraw SFINCS filename/parameterを露出させません。

# 1. 対象画面環境

v0.1はPCブラウザ向け。

- 主対象: 1280×720以上;
- 最低: 1024×700;

1024px未満:

# 4. 常時表示の制限事項bar

SETUP/RESULTで常時表示。

compact文言:

> `下水・浸透は未考慮 / 雨は解析範囲内で一様 / 公的な洪水予報・避難情報ではありません`

`詳しく見る`を配置。

詳細に必須:

- 浸透未考慮;
- 下水道・雨水管・排水口・ポンプ未考慮;
- 建物内部浸水なし;
- 気象降雨は範囲内同一;
- 屋根雨量は近傍地表へ質量保存再配分する近似;
- 河川水位・潮位・高潮連成なし;
- 公的な警報・避難判断の代替ではない。

barはcollapse可だが、永久dismiss不可。

# 5. Step 1 — 場所

見出し:

```text
1. 場所
```

## 検索

label:

```text
住所・地名を検索
```

placeholder:

```text
例: 新宿駅 / 東京都千代田区千代田1-1
```

- Enter/search iconで実行;
- `検索中…`;
- 最大10候補;
- candidateにtitle、必要ならconfidence/detail;
- raw provider JSONなし。

選択時:

- map移動;
- center marker;
- analysis center設定;
- candidate list閉じる。

CSIS利用時帰属:

> `住所・地名検索: CSISシンプルジオコーディング実験を利用`

## 緯度経度直接入力

control:

```text
緯度経度を直接入力
```

fields:

```text
緯度 [          ]
経度 [          ]
[この位置へ移動]
```

validation:

```text
緯度は -90〜90、経度は -180〜180 の範囲で入力してください。
```

geocoder offlineでも使える。

## Map click

rectangle drawing中でなければmap clickでcenter移動可。


# 7. Step 3 — 雨

見出し:

```text
3. 雨
```

Tab:

```text
[過去の豪雨] [雨量を指定]
```

## 過去の豪雨

area center近傍観測地点を表示。

rectangle-onlyならcentroidをstation searchにのみ使う。analysis areaは変更しない。

```text
観測地点: [東京都 東京 ▼]
解析中心から 18.4 km
```

historical row:

```text
観測史上 1位
1時間降水量 91.5 mm
2022-08-03
```

### 均等降雨

label:

```text
総雨量を時間内に均等に降らせる
```

説明:

```text
例: 1時間で91.5 mmなら、解析範囲全体に91.5 mm/hを1時間降らせます。
実際の雨の時間変化を再現するものではありません。
```

valid historical eventでは常に利用可。

### 実観測時系列

label:

```text
実際の観測時系列を使う
```

`profile_available=true`のみenable。

不可:

```text
この記録は時系列データを準備できていません。
```

## 任意雨量

```text
雨量強度 [100.0] mm/h
継続時間 [60] min
```

下に:

```text
総雨量: 100.0 mm
```

silent round禁止。

## Summary

```text
雨: 100 mm/h × 60分
総雨量: 100 mm
空間分布: 解析範囲内で一様
```

observed profileでは単一強度を表示しない。

# 8. Step 4 — 精度

見出し:

```text
4. 精度
```

radio cardは2つだけ。

## Full

```text
高精度 — 全域1 m
```

説明:

```text
解析範囲全体を1 m格子で計算します。
最も細かい比較基準ですが、広い範囲ではメモリと計算時間が大きくなります。
```

internal: `full_1m`。

## Adaptive

```text
自動最適化 — Adaptive
```

説明:

```text
建物・道路・細かな地形は細かく保ち、細かく計算しても精度上の利点が小さい場所だけ2〜32 mへ粗くします。
粗い格子でも高解像度地形をsubgrid情報として利用します。
```

validation前badge:

```text
実験的
```

validation合格後にproduct decisionで:

```text
推奨
```

frontend独自判断禁止。backend capabilityに従う。

validation前defaultは `full_1m`。

# 9. Resource preview / run summary

`解析開始`直前card:

```text
場所       <位置>
範囲       <width × height / area>
雨         <scenario>
精度       <Full 1 m / Adaptive>
推定格子   <count or 概算>
負荷       <小 / 中 / 大 / 非常に大>
```

Adaptive estimate未確定は`概算`。

warning例:

```text
この範囲を全域1 mで計算すると非常に大きなメモリを使用する可能性があります。
高性能PCではそのまま実行できます。必要ならAdaptiveを選択してください。
```

自動mode切替禁止。

# 11. 進捗

run開始後setupはread-only/disabled、mapは残す。

stage label:

```text
VALIDATING            条件を確認しています
ACQUIRING_TERRAIN     標高データを取得しています
ACQUIRING_VECTORS     建物・道路データを取得しています
ACQUIRING_RAINFALL    雨量データを確認しています
PREPROCESSING_TERRAIN 地形を準備しています
ALLOCATING_ROOF_RAIN  屋根雨水を再配分しています
BUILDING_GRID         計算格子を作成しています
BUILDING_MODEL        SFINCSモデルを作成しています
ENSURING_ENGINE       計算エンジンを確認しています
RUNNING_ENGINE        洪水計算を実行しています
READING_RESULTS       結果を読み込んでいます
```

backendがprogressを出したときのみ%。SFINCSはfake%禁止。

elapsed time可、remaining ETAなし。

PLATEAU→OSM fallback:

```text
この範囲ではPLATEAUの建物情報を利用できなかったため、OpenStreetMapを使用しています。
結果のデータ出典に記録されます。
```

Cancel:

```text
解析を中止
```

confirm:

```text
解析を中止しますか？
途中結果は完成結果として利用できません。
```

# 12. Failure UI

表示:

- stage;
- Japanese concise message;
- retryable;
- `詳細`にcode;
- `条件に戻る`;
- retryableのみ`再試行`。

stack trace default非表示。

Geocoder:

```text
住所検索サービスに接続できません。
緯度経度を直接入力して解析を続けることができます。
```

SFINCS:

```text
計算エンジンを準備できませんでした。
ネットワーク接続またはエンジン設定を確認してください。
```

# 18. 解析条件と出典

collapsible panelに:

- bounds;
- rainfall station/date/mode;
- accuracy;
- grid level counts;
- GSI source class;
- building/road provider;
- fallback;
- SFINCS/HydroMT/app version;
- Manning;
- boundary;
- roof mass diagnostic;
- limitations。

通常ユーザーがraw manifestを開かなくても基本provenanceを確認可能。

# 19. 新しい解析

`新しい解析`:

- SETUPへ戻る;
- previous location/area/rain/accuracyをeditable defaultとして保持;
- prior result/run file削除しない;
- destructiveでないのでconfirm不要。

# 21. Accessibility

必須:

- visible label;
- focus indicator;
- Tab order 1→4→run;
- Enterはgeocoder submitのみ、simulation startしない;
- safe modalはEscape;
- color only status禁止;
- WCAG AA相当contrast;
- semantic disabled;
- loading text screen reader対応。

rectangle mouse操作が困難でもcenter presetでessential setup可能。

---

# 22. Loading/empty/offline

backend unavailable:

```text
ローカル解析サービスに接続できません。
アプリを再起動してください。
```

map tile unavailable:

```text
背景地図を読み込めません。ネットワーク接続を確認してください。
```

selected areaは消さない。

geocoder unavailable→manual lat/lon。

rainfall catalog corrupt→`過去の豪雨` disabled、custom雨は使える。

# 23. UI state invariants

- `解析開始` enableはderived。
- map表示areaとAPI areaは同一state。
- accuracy label/API enumは同一state。
- rainfall summary/submissionは同一resolved scenario。
- timeline label/time_indexは同一state。
- RESULT limitationsはbackend metadata由来。
- provider表示はbackendが実際に使用したprovider。

全てテスト必須。

---

# 24. UI受入flow

## A preset + custom + Full

場所→±500m→100mm/h 60min→Full→review→run→progress→result→point inspect→limitations。

GIS/SFINCS手作業なしでpass。

## B historical + Adaptive

場所→rectangle→JMA station→rank event→uniform→Adaptive→run→grid layer→metadata。

Adaptive backend capability enable時のみ。

## C geocoder failure

failure説明→lat/lon直接入力→継続。

## D provider fallback

PLATEAU不可→OSM成功→notification→result metadataにOSM。

## E cancel

active→cancel→confirm→cancelled→setup再編集→partial resultをcomplete表示しない。

# 27. 最終確認

初回ユーザーが **どこ / どの範囲 / どんな雨 / どの精度** の4点だけを理解して解析でき、同時に「これは限定された数値scenarioで公的洪水予報ではない」と常に把握できることがUIの合格条件です。
