## 目的と分岐

現在のサンプル条件を水魔法の選択に置き換える。魔法のイメージと給水範囲を地図上で確認し、地形に沿って水が広がる様子を解析する。

既存 v0.1 仕様は地形取得・格子・実行・結果表示に引き続き適用する。本仕様が水魔法版の選択UI・給水条件を上書きする。

## 利用の流れと画面

1. 地図と解析領域を設定する。
2. 水魔法を選ぶと、その時点の表示地図の中心に魔法を配置する。
3. 魔法のイメージ、実際に水を加える範囲、必要なら方向矢印を重ねて表示する。
4. 専用の簡易UIで位置・方向・範囲・水量・持続時間・緩和時間を設定する。
5. 確定した条件で解析し、給水中と給水終了後をタイムラインで確認する。

WM-02: 魔法一覧には固定ID、版、名称、説明、画像、形状、操作項目、初期値、上下限、水量の定義、持続時間、モデルの近似説明を持たせる。具体的な魔法名や値はリンク先本文を確認してから決める。

WM-03: 選択時に置いた位置は緯度経度として保持する。地図を移動・拡大しても魔法は勝手に追従しない。「地図の中心に配置」操作で置き直し、位置を調整できる。解析領域と魔法の範囲は別に扱う。

WM-04: 演出用画像と解析に使う給水範囲を区別する。画像サイズから水量・範囲を決めない。地形と解析境界を見える状態に保つ。画像がない場合は名称付きの簡易シンボルで代替する。

WM-05: 専用UIの候補は次のとおり。これは魔法一覧の確定案ではなく、形状別の操作提案である。各操作には数値入力を併設する。

| 形状 | 操作 |
| --- | --- |
| 円 | 半径 |
| 扇形 | 半径・開き角・方向 |
| 帯状の長方形 | 長さ・幅・方向 |
| 任意の多角形 | 頂点編集・戻す・リセット |

距離は m、方向は真北を0度とする時計回りで、地図の回転とは独立。長方形は配置点から指定方向へ伸び、幅方向は配置点を中心にする。

WM-06: 総水量 m³、持続時間 秒、平均給水量 m³/s、有効面積 m²、相当水深・相当降雨強度を表示する。面積を変更しても総水量は無断で変えない。流量で定義された魔法も実行前に総水量へ換算する。

WM-09: 実行開始時に条件と形状を固定する。条件変更で古いプレビューを無効化する。「新しい解析」で設定を保持して編集に戻り、再実行では別の解析IDを作る。

WM-10: 結果に給水中／緩和中の区別を表示し、魔法の範囲を表示切替できる。水深・流速・タイムライン・地点確認は既存結果機能を使う。最大値は解析全時間を対象とする。演出画像を浸水結果として扱わない。

WM-11: 魔法の版・確定設定・配置・座標系・給水条件・チェックサム・水量報告・格子・エンジン情報を保存する。読込時に最新の初期値へ置換しない。従来の降雨結果は降雨結果と表示する。「サンプルまたは読込み」のサンプル選択部分を置換し、結果ファイル読込は別の明確な操作として残す。

## 解析の考え方

WM-07: 全域一様の雨を使わず、指定範囲だけに水を加える。範囲外はゼロ。初期案は固定位置・一定流量・1回の発動・背景降雨なし・Full 1 m。Adaptive は無効のままとし、他の格子は別途検証する。

WM-08: **解析時間 = 魔法の持続時間 + 水が広がる緩和時間**。持続時間は正の有限値、緩和時間は0以上の有限値。両方と合計を画面・保存データに持つ。緩和時間は初期案では利用者が指定する観察時間で、平衡に達した保証ではない。給水終了後も溜まった水は残り得る。

総水量 V、持続時間 T とすると平均流量は Q=V/T。各格子への量は、給水範囲と有効格子の交差面積に応じて配分する。セル全体の面積 A_i、交差面積 a_i、有効面積の合計 A とすると、セルの水深増加率は Q×a_i/(A×A_i) m/s。mm/hへの換算係数は3,600,000。全セルの給水量を合計した値が指定流量に一致する。

交差面積は解析用のメートル座標系で計算し、緯度経度の度数を距離・面積に使わない。格子中心だけの判定で小さな魔法を消してはならない。解析領域からはみ出す範囲は、初期方針として拒否する。建物等により受水できない部分は、有効面積・配分方針を実行前に示し、変化した有効範囲を明示して確認する。有効面積ゼロは拒否する。屋根処理で水が重複・消失しないことを検証する。この配分方針は Ready 化前に確定が必要。

方向は給水範囲の向きに反映する。水を高速で撃ち出す運動量・圧力は、この局所給水モデルでは再現しない。噴流型の魔法を再現済みとは表示しない。移動魔法・吸水・障壁・複数同時発動・侵食・破壊は初期対象外。

WM-12: 秒単位の魔法に対応するため、給水開始・終了・解析終了を結果時刻として捉え、給水中の変化を追える出力間隔を検証する。既存の分単位出力を無条件に流用しない。エンジン都合で丸める場合は実行前に明示し、未対応なら実行を止める。

## 現行実装との境界

確認した現行コードは以下。新機能の実動作を確認したものではない。

| ファイル | 確認事項 |

## エラーと制約

非有限値・負値・水量ゼロ・持続時間ゼロ・不正多角形・領域外・有効面積ゼロ・未対応版・計算予算超過は拒否する。水量の無断切り下げや全域平均雨への代替は禁止。エンジン未対応、時間補間、屋根配分、物理的な意味に未解決事項がある場合は仕様修正として扱う。

給水終了後のゼロ指定は生成ファイルと実エンジンで確認する。時刻端点だけでは、補間で緩和時間中に水が入り続けない証拠にならない。大きな局所水量による水深・時間刻み・メモリ増大を事前見積りする。浸透・粗度・境界条件は既存設定を明示して記録する。

## 受入条件と検証

- AC-01: 保存タグが指定main SHAを指し、今回の差分は仕様書だけ。
- AC-02: 選択時の地図中心配置、位置保持、明示的な再配置、回転地図での方向・数値入力の一致をブラウザで確認する。
- AC-03: 不正値・形状・未対応の物理魔法は実行不可。画像欠落でも名称付きプレビューが使える。
- AC-04: float64の形状・時間積分で指定水量との相対誤差1e-6以下、エンジン向け保存データで1e-4以下。範囲外・緩和中の定義給水はゼロ。エンジン補間方式で積分する。
- AC-05: 平坦・閉境界・損失なしの給水のみの実エンジン試験で最終貯留水量の誤差1%以下。無給水の対照試験で水が生成されない。これらは受入基準案で、実施済みではない。
- AC-06: 円・扇形・長方形・部分セル、領域外・不正・受水不可の試験。地形上の拡散と緩和中の追加給水なしを実エンジンで確認する。
- AC-07: 5秒発動＋60秒緩和の試験案で発動終了と拡散を捉え、分単位へ丸めない。未対応なら Ready 化前に能力・対象範囲を見直す。
- AC-08: 書出し／読込で配置・水量・時間・版を再現し、既存降雨結果と既存結果操作も回帰確認する。

今回は文書構造・参照・基点・限定差分・`git diff --check` を検証する。製品UIや水理の受入試験は実装後。実装時は独立した品質チェックを先に行い、形状／水量／時刻のテスト、API／保存互換試験、実エンジン試験、ブラウザ操作、必要な回帰・ビルド確認を行う。Pythonは正規の `urban-pluvial-flood-phase0` 環境を使い、SHA・バージョン・コマンド・終了コード・成果物を記録する。
