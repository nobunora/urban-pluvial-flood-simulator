# Urban Pluvial Flood Simulator v0.1 — UI Behavior Specification

> Status: Draft UI contract
>
> Canonical language: English. User-facing strings specified here are Japanese because v0.1 UI language is Japanese.
>
> Product source of truth: `docs/PRODUCT_SPEC_DRAFT.md`.
>
> Backend/system source: `docs/specs/v0.1-implementation-spec.md`.
>
> This document defines **what the user sees and can do**. Frontend code structure is defined separately in `docs/specs/v0.1-ui-implementation-spec.md`.

---

# 0. Interpretation and non-negotiable UI rules

The UI MUST:

- be understandable without GIS or hydraulic-model knowledge;
- keep the four primary user decisions visible: **場所 / 範囲 / 雨 / 精度**;
- keep important modelling omissions continuously discoverable;
- never present a historical scenario as an actual future forecast;
- never hide provider fallback, failed data quality, or missing capability;
- never display a fake solver progress percentage;
- never silently change Full 1 m to Adaptive;
- never silently change rainfall mode or duration;
- never enable a control whose prerequisites are invalid.

The UI MUST NOT expose raw SFINCS filenames or parameters in the normal path.

### Chapter check

- Target alignment: yes — ordinary users see only decisions that matter.
- Do now: simple Japanese desktop-browser interface.
- Do later: expert/English/mobile modes.
- Permanent non-goal: misleading certainty or hidden assumptions.

# 1. Supported display environment

v0.1 targets desktop/laptop browsers opened by the local application.

Supported layout targets:

- primary: 1280×720 and larger;
- minimum supported: 1024×700;
- browser zoom 100% reference;
- modern Chrome/Edge/Firefox.

Mobile/touch-first layout is not required in v0.1.

At widths below 1024 px, show:

> `このバージョンはPC向けです。ウィンドウ幅を広げてください。`

Do not attempt a separate mobile design in v0.1.

# 4. Persistent limitation bar

This bar is always visible in SETUP and RESULT modes.

Default compact text:

> `下水・浸透は未考慮 / 雨は解析範囲内で一様 / 公的な洪水予報・避難情報ではありません`

The bar includes `詳しく見る`.

Expanded limitations MUST state at least:

- 浸透を考慮していない;
- 下水道・雨水管・排水口・ポンプを考慮していない;
- 建物内部の浸水を計算していない;
- 雨量は解析範囲内で同一の気象降雨を仮定している;
- 屋根雨水は周囲の地表へ質量保存で再配分する近似で、実際の雨樋・排水先ではない;
- 河川水位・潮位・高潮との連成は行わない;
- 結果は数値シナリオであり、公的な警報・避難判断の代替ではない.

The compact bar may be collapsed but MUST NOT be dismissible permanently.

# 5. Step 1 — 場所

Section title:

```text
1. 場所
```

## 5.1 Search input

Label:

```text
住所・地名を検索
```

Placeholder:

```text
例: 新宿駅 / 東京都千代田区千代田1-1
```

Actions:

- Enter or search icon starts search.
- While searching: spinner + `検索中…`.
- Up to 10 candidates shown below input.

Candidate row:

- provider-returned title;
- optional detail/confidence only when meaningful;
- no raw provider JSON.

Selecting candidate:

- moves map;
- places center marker;
- sets analysis center;
- closes candidate list.

Geocoder attribution when CSIS configured:

> `住所・地名検索: CSISシンプルジオコーディング実験を利用`

This attribution is visible near search results or in an always-accessible attribution area.

## 5.2 Coordinate input

Link/control:

```text
緯度経度を直接入力
```

Expanded fields:

```text
緯度 [          ]
経度 [          ]
[この位置へ移動]
```

Validation is immediate but not disruptive.

Invalid:

```text
緯度は -90〜90、経度は -180〜180 の範囲で入力してください。
```

Manual coordinates remain usable even when geocoder is offline.

## 5.3 Map click

A map click MAY set/move the candidate center when area drawing mode is not active.

The selected center marker is clearly visible.

# 6. Step 2 — 範囲

Section title:

```text
2. 範囲
```

Mode control:

```text
[中心から指定] [地図で矩形指定]
```

Exactly one mode is active.

## 6.1 Center preset

Buttons:

```text
±250 m
±500 m
±1000 m
±2000 m
```

Default after a center exists:

```text
±500 m
```

A preset creates a square centered on selected center.

Display below:

```text
範囲: 1.00 km × 1.00 km
面積: 1.00 km²
```

If no center exists, preset buttons are disabled and helper text says:

```text
先に場所を指定してください。
```

## 6.2 Rectangle mode

Instruction overlay:

```text
地図上をドラッグして解析範囲を指定してください。
```

During drag, draw translucent rectangle.

After release, show width/height/area in left panel.

Controls:

- `範囲を描き直す`
- `中心に戻る` only when a search/manual center exists.

A completed rectangle becomes the analysis area regardless of center marker.

## 6.3 Area validation

Zero/invalid rectangle is rejected.

v0.1 does not impose an arbitrary small maximum area at UI level. Resource warnings handle large jobs.

# 7. Step 3 — 雨

Section title:

```text
3. 雨
```

Top-level tabs:

```text
[過去の豪雨] [雨量を指定]
```

Advanced arbitrary CSV editing is not required in the normal UI v0.1.

## 7.1 Historical rainfall

First show nearest observation stations after area center is known.

Station selector row:

```text
観測地点: [東京都 東京 ▼]
解析中心から 18.4 km
```

If the area has no center because rectangle was drawn manually, use rectangle centroid only for nearest-station search. Do not alter analysis area.

### Historical event list

Rows/cards show:

- duration: e.g. `1時間` / `24時間`;
- precipitation total;
- rank if available;
- date;
- station name.

Example:

```text
観測史上 1位
1時間降水量 91.5 mm
2022-08-03
```

Selecting event reveals mode choices.

### Equivalent-uniform mode

Label:

```text
総雨量を時間内に均等に降らせる
```

Explanation:

```text
例: 1時間で91.5 mmなら、解析範囲全体に91.5 mm/hを1時間降らせます。
実際の雨の時間変化を再現するものではありません。
```

This mode is always available for a valid historical catalog event.

### Observed-profile mode

Label:

```text
実際の観測時系列を使う
```

Only enabled when `profile_available=true`.

When unavailable:

```text
この記録は時系列データを準備できていません。
```

Do not present a disabled profile as an error.

## 7.2 Custom rainfall

Fields:

```text
雨量強度     [100.0] mm/h
継続時間     [60] min
```

Validation ranges are backend contract ranges.

Below fields show derived total:

```text
総雨量: 100.0 mm
```

Do not round input values silently.

## 7.3 Rainfall summary

Once valid:

```text
雨: 100 mm/h × 60分
総雨量: 100 mm
空間分布: 解析範囲内で一様
```

For historical observed profile, show total and duration, not a misleading single intensity.

# 8. Step 4 — 精度

Section title:

```text
4. 精度
```

Two large radio cards only.

## 8.1 Full 1 m

Title:

```text
高精度 — 全域1 m
```

Description:

```text
解析範囲全体を1 m格子で計算します。
最も細かい比較基準ですが、広い範囲ではメモリと計算時間が大きくなります。
```

Internal value: `full_1m`.

## 8.2 Adaptive

Title:

```text
自動最適化 — Adaptive
```

Description:

```text
建物・道路・細かな地形は細かく保ち、細かく計算しても精度上の利点が小さい場所だけ2〜32 mへ粗くします。
粗い格子でも高解像度地形をsubgrid情報として利用します。
```

Internal value: `adaptive`.

Badge before Adaptive validation gate passes:

```text
実験的
```

After gate passes and product decision changes, badge may become:

```text
推奨
```

The frontend does not decide this locally; capability comes from backend/app configuration.

Default v0.1 selection before validated recommendation:

```text
full_1m
```

Do not default to Adaptive until validation gate passes.

# 9. Resource preview and run summary

Immediately above `解析開始`, show a summary card.

Required rows:

```text
場所       <selected place/coordinates or rectangle center>
範囲       <width × height / area>
雨         <scenario summary>
精度       <Full 1 m / Adaptive>
推定格子   <count or preliminary>
負荷       <小 / 中 / 大 / 非常に大>
```

If Adaptive preliminary estimate is not yet available, label:

```text
概算
```

Warnings are yellow, not red, unless run is technically impossible.

Example warning:

```text
この範囲を全域1 mで計算すると非常に大きなメモリを使用する可能性があります。
高性能PCではそのまま実行できます。必要ならAdaptiveを選択してください。
```

Do not automatically switch modes.

# 10. 解析開始 button

Primary button label:

```text
解析開始
```

Enabled only when all are true:

- valid analysis area;
- valid rainfall scenario;
- selected accuracy mode;
- backend healthy;
- no active run.

Disabled state has specific helper text, not generic `入力してください`.

Click opens a final review sheet/panel, not a new page.

Review includes:

- area;
- rainfall;
- accuracy;
- important limitations;
- resource class.

Buttons:

```text
[戻る] [この条件で解析開始]
```

No mandatory “I agree” checkbox in v0.1 because limitations are already persistent. The confirmation panel is informational and prevents accidental run.

# 11. Run/progress UI

When run starts:

- setup controls become read-only/disabled;
- map remains visible;
- left panel switches to progress view;
- persistent limitations remain visible.

## 11.1 Stage labels

Map backend stages to these Japanese labels:

```text
VALIDATING            条件を確認しています
ACQUIRING_TERRAIN     標高データを取得しています
ACQUIRING_VECTORS     建物・道路データを取得しています
ACQUIRING_RAINFALL    雨量データを確認しています
PREPROCESSING_TERRAIN 地形を準備しています
ALLOCATING_ROOF_RAIN  屋根雨水を再配分しています
BUILDING_GRID         計算格子を作成しています
BUILDING_MODEL        SFINCSモデルを作成しています
ENSURING_ENGINE       計算エンジンを確認しています
RUNNING_ENGINE        洪水計算を実行しています
READING_RESULTS       結果を読み込んでいます
```

## 11.2 Progress representation

- determinate percentage only when backend provides one;
- otherwise use indeterminate spinner/bar;
- SFINCS stage MUST NOT show fake percent.

Elapsed time MAY be shown.

Do not show an estimated remaining time in v0.1.

## 11.3 Provider fallback notice

If PLATEAU → OSM fallback occurs, show non-blocking notice:

```text
この範囲ではPLATEAUの建物情報を利用できなかったため、OpenStreetMapを使用しています。
結果のデータ出典に記録されます。
```

## 11.4 Cancel

Button:

```text
解析を中止
```

Click asks:

```text
解析を中止しますか？
途中結果は完成結果として利用できません。
```

Buttons:

```text
[続ける] [中止する]
```

During cancellation:

```text
停止処理中…
```

# 12. Failure UI

Failure card contains:

- stage label;
- concise Japanese message;
- whether retry may help;
- `詳細` expandable developer/error code;
- `条件に戻る`;
- `再試行` only if backend marks retryable.

Do not display stack traces by default.

Examples:

### Geocoder unavailable

```text
住所検索サービスに接続できません。
緯度経度を直接入力して解析を続けることができます。
```

### PLATEAU strict data failure where no allowed fallback

```text
建物・道路データを準備できませんでした。
詳細を確認してください。
```

### SFINCS engine unavailable

```text
計算エンジンを準備できませんでした。
ネットワーク接続またはエンジン設定を確認してください。
```

Two selectable color modes:

```text
深さ区分
レインボー
```

Default: `深さ区分`.

## 15.1 Depth bands

Bands:

0.05–0.10 m

# 16. Timeline

Visible only for `時刻別の浸水深`.

Controls:

```text
[◀] [▶]
00:00 ─────●──────── 01:00
現在: 00:37
```

Slider snaps to actual available output times.

Do not interpolate a fake intermediate model state in UI.

# 18. Result metadata / provenance panel

Collapsible `解析条件と出典` panel contains:

- analysis bounds;
- rainfall source/station/date/mode;
- accuracy mode;
- final grid-level counts;
- GSI terrain source classes actually used;
- building/road provider;
- fallback note;
- SFINCS version;
- HydroMT-SFINCS version;
- application version;
- general/road Manning values;
- boundary policy summary;
- roof-rain mass diagnostic summary;
- model limitations.

Do not require users to open raw manifest for basic provenance.

Advanced link MAY expose/download `manifest.json` later; not required for basic UI acceptance.

# 19. New analysis behavior

Button:

```text
新しい解析
```

- return to SETUP;
- retain previous location/area/rainfall/accuracy as editable defaults;
- do not delete prior result/run files;

`条件` in RESULT can open a read-only summary without switching back.

アプリ情報

# 21. Accessibility and keyboard behavior

Required:

- every form control has visible label;
- focus indicator visible;
- logical Tab order follows steps 1→4→run;
- Enter submits geocoder but not full simulation;
- Escape closes modal/popup where safe;
- status is not conveyed by color alone;
- text contrast targets WCAG AA;
- buttons have disabled semantics, not only visual gray;
- loading status has text for screen readers.

Map-only rectangle drawing has an alternative via center presets, so essential analysis setup does not require precision mouse drawing.

# 22. Loading, empty, and offline states

## Backend unavailable

Full-page state:

```text
ローカル解析サービスに接続できません。
アプリを再起動してください。
```

## Map tiles unavailable

Controls remain usable where possible.

Show map notice:

```text
背景地図を読み込めません。ネットワーク接続を確認してください。
```

Do not erase selected coordinates/area.

## Geocoder unavailable

Manual lat/lon remains available.

## Rainfall catalog unavailable/corrupt

Hide/disable `過去の豪雨` with clear error; custom rainfall remains available.

## PLATEAU unavailable

Handled during run, not setup, unless preflight provider coverage information is available.

# 23. Exact UI state invariants

- `解析開始` enabled state is derived, never independently toggled.
- Area displayed on map and area sent to API come from the same state object.
- Selected accuracy label and API enum come from the same state object.
- Rainfall summary and submitted rainfall payload come from the same resolved scenario object.
- Result timeline label and requested `time_index` come from the same selected time state.
- Limitations displayed in RESULT are sourced from backend result metadata, not a frontend-only hard-coded subset.
- Provider name displayed is backend-reported provider actually used.

These invariants are mandatory tests.

# 24. UI acceptance flows

## Flow A — preset + custom rain + Full

1. launch app;
2. search/select location or enter coordinates;
3. choose ±500 m;
4. choose custom `100 mm/h`, `60 min`;
5. choose `高精度 — 全域1 m`;
6. review summary;
7. start;
8. observe stage updates;
9. reach RESULT;
10. see max-depth overlay;
11. click a data point;
12. see units and limitations.

Pass: no GIS/SFINCS manual step.

## Flow B — historical event + Adaptive

1. select location;
2. choose rectangle;
3. choose nearest JMA station;
4. choose ranked event;
5. choose equivalent-uniform mode;
6. choose Adaptive;
7. run;
8. RESULT includes grid-resolution layer;
9. metadata identifies rainfall station/event and final grid counts.

Pass only if Adaptive backend capability is enabled.

## Flow C — geocoder failure

1. geocoder returns unavailable;
2. UI explains failure;
3. user expands coordinate input;
4. manual coordinate selection works;
5. simulation setup remains possible.

## Flow D — provider fallback

1. PLATEAU unavailable/no usable building data;
2. allowed OSM fallback succeeds;
3. UI surfaces fallback notification;
4. result metadata identifies OSM.

## Flow E — cancel

1. run reaches active stage;
2. user cancels;
3. confirm;
4. state becomes cancellation then cancelled;
5. setup can be edited/re-run;
6. partial result not presented as complete.

# 25. UI completion criteria

- [ ] SETUP and RESULT layouts match the defined information hierarchy.
- [ ] Persistent limitation bar exists in both modes.
- [ ] Address/place search and coordinate fallback are usable.
- [ ] Preset squares and drawn rectangle work.
- [ ] Historical and custom rainfall are distinguishable.
- [ ] Uniform historical mode is explicitly described as hypothetical redistribution.
- [ ] Full/Adaptive are the only accuracy cards.
- [ ] Adaptive experimental/recommended state comes from backend capability.
- [ ] Resource preview never silently changes settings.
- [ ] Final review precedes run.
- [ ] Progress uses backend stages and no fake engine percentage.
- [ ] Cancellation semantics are visible and correct.
- [ ] Failure UI maps stable errors to understandable Japanese messages.
- [ ] Max depth is default result layer.
- [ ] Time-depth and grid-resolution layers work.
- [ ] Point inspection distinguishes no-data from zero.
- [ ] Result provenance is visible.
- [ ] Limitations remain visible in results.
- [ ] Required keyboard/accessibility behavior passes tests.
- [ ] All acceptance flows pass in Playwright with deterministic mocks; required local SFINCS smoke flow passes before release.

# 26. Explicit UI non-goals v0.1

Do not implement:

- mobile-first interface;
- 3D flood rendering;
- building interior view;
- expert numerical parameter editor;
- sewer/infiltration toggles;
- live weather forecast dashboard;
- multi-run comparison UI;
- batch queue UI;
- user accounts;
- cloud sharing;
- damage/cost estimates;
- official warning language.

# 27. Final target check

The UI is acceptable only if a first-time non-specialist can complete the primary flow by understanding four decisions — **where, area, rain, accuracy** — while the application continuously communicates that the result is a limited numerical scenario rather than an official flood forecast.
