# Specifications

This directory contains implementation-independent contracts that are shared through GitHub before repository implementation begins.

Use one file per coherent change. Prefer stable names such as:

```text
docs/specs/<feature-or-change>.md
```

Start from `SPEC_TEMPLATE.md`.

A specification states what must be true. It must not claim repository compatibility until repository review has validated it against the current source tree.

When a specification is ready for repository review, its PR may be labeled `codex-ready`.
