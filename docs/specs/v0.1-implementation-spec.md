# 1. v0.1 system outcome

## 1.1 Required end-to-end outcome

A user on a normal Windows PC SHALL be able to:

```text
launch local application
→ browser opens local UI
→ search location or enter coordinates
→ select rectangle or ±250/500/1000/2000 m area
→ select historical/custom rainfall
→ choose Full 1 m or Adaptive
→ start simulation
→ application automatically obtains required public data
→ application prepares SFINCS model
→ application ensures a compatible SFINCS engine is available
→ SFINCS runs
→ application normalizes results
→ maximum depth appears on map
→ user can inspect time-dependent depth and point values
```

No manual GIS conversion or SFINCS input editing is permitted in the default flow.

## 1.2 Local-first v0.1

v0.1 is a **local application with a browser-based UI**.

Architecture:

```text
Browser
  │ HTTP on loopback only
  ▼
FastAPI application
  ├─ data providers
  ├─ preprocessing
  ├─ rainfall
  ├─ grid generation
  ├─ HydroMT-SFINCS model preparation
  ├─ SFINCS process runner
  ├─ result normalization/rendering
  └─ cache / manifest / project state
       │
       ▼
SFINCS v2.4.0 Galibier
```

The local server MUST bind only to `127.0.0.1` by default.

Hosted/multi-user browser execution is not part of v0.1.

### Chapter check

- Product alignment: yes — near-zero setup and future browser reuse.
- Do now: local loopback application.
- Do later: hosted browser service.

# 4. Domain contracts

All API-visible contracts SHALL be Pydantic models with `schema_version` where persisted.

## 4.1 Coordinate conventions

API geographic coordinates:

```text
longitude: float degrees, EPSG:4326
latitude:  float degrees, EPSG:4326
```

Arrays and internal projected products MUST explicitly record CRS and row orientation.

Never use an unlabeled two-number tuple for coordinates across module boundaries.

Required domain types:

```text
LonLat { lon_deg, lat_deg }
GeoBounds { west_deg, south_deg, east_deg, north_deg }
ProjectedBounds { xmin_m, ymin_m, xmax_m, ymax_m, crs }
```

## 4.2 Area selection

`AnalysisArea` SHALL contain:

- `mode`: `preset_square | rectangle`;
- EPSG:4326 bounds;
- center coordinate;
- width_m;
- height_m;
- area_m2.

Preset half sizes allowed in v0.1:

```text
250, 500, 1000, 2000 m
```

## 4.3 Accuracy mode

Exact values:

```text
full_1m
adaptive
```

No other user-visible accuracy mode exists in v0.1.

## 4.4 Rainfall scenario

Discriminated union:

```text
ConstantRainfall
HistoricalUniformRainfall
HistoricalObservedProfile
```

All scenarios SHALL resolve before model build to:

```text
RainfallTimeSeries
- start_time
- elapsed_seconds[]
- intensity_mm_per_h[]
- source metadata
- meteorological_spatial_mode = uniform
```

Roof redistribution is a hydraulic forcing correction and MUST NOT change the user-facing statement that meteorological rainfall is spatially uniform.

- projected CRS;
- requested accuracy mode;
- final grid level counts;
- elevation provider counts/resolution;
- building/road providers;
- geocoder provider only if used;
- rainfall scenario + source;
- SFINCS version/build SHA;
- HydroMT-SFINCS version;
- Manning defaults;
- boundary policy;
- roof-rain mass diagnostic;
- explicit omitted-process flags;
- run status;
- output file identities/checksums where practical.

# 5. Local server and process model

## 5.1 Server lifecycle

Normal packaged launch:

```text
application executable
→ choose free loopback port
→ start FastAPI/Uvicorn on 127.0.0.1 only
→ wait for /api/v1/health success
→ open default browser
→ serve SPA and API from same origin
```

Do not bind `0.0.0.0` in v0.1 default mode.

## 5.2 Concurrency

v0.1 supports **one active simulation per application instance**.

Starting a second run while one is active SHALL return HTTP `409` with code `RUN_ALREADY_ACTIVE`.

Read-only result endpoints MAY be used while no conflicting file write is occurring.

## 5.3 Background execution

Long-running simulation workflow MUST NOT block the FastAPI request thread.

Use one application-owned background worker/executor for the active run. Do not add Celery/Redis.

## 5.4 Cancellation

Cancel request:

1. mark run `CANCELLING`;
2. stop starting new stages;
3. if SFINCS process exists, send graceful termination;
4. wait at most 5 seconds;
5. force-kill if still alive;
6. mark `CANCELLED`;
7. retain logs and manifest;
8. do not expose partial result as completed output.

## 5.5 Local web security

- same-origin UI/API only;
- CORS disabled by default;
- bind to loopback only;
- mutation endpoints accept `application/json` only;
- reject unsupported `Content-Type` with 415;
- do not log raw address-search strings at info level;
- do not expose filesystem paths in normal user errors;
- sanitize filenames generated from user labels.

### Chapter check

- Product alignment: yes — safe, responsive local browser experience.
- Do now: one run, loopback, cancellable process.
- Do later: multi-user scheduling in hosted product.
- Permanent non-goal: public network listener by default.

# 6. REST API contract

All routes use prefix `/api/v1`.

Error body:

```json
{
  "error": {
    "code": "STABLE_CODE",
    "message": "Japanese user-facing message",
    "stage": "OPTIONAL_STAGE",
    "retryable": false
  }
}
```

Do not expose Python tracebacks in API responses.

## 6.1 Health

`GET /api/v1/health`

Returns app version, API version, engine availability summary, and status `ok` when server can accept UI requests.

## 6.2 Geocode

`GET /api/v1/geocode?q=<text>`

Rules:

- trim input;
- reject empty input;
- max 200 Unicode code points;
- return at most 10 candidates;
- each candidate has title, lon, lat, provider, confidence/detail metadata if provided upstream.

Default v0.1 geocoder is **CSIS Simple Geocoding Experiment** because its current terms explicitly cover standalone/web applications and require visible attribution.

The UI MUST display the required CSIS attribution when this provider is configured.

If CSIS is unavailable, geocoding fails with `GEOCODER_UNAVAILABLE`; the user may still enter latitude/longitude manually. Do not silently switch to GSI msearch or Nominatim without a specification revision.

## 6.3 Rainfall catalog

`GET /api/v1/rainfall/stations?lon=&lat=&limit=5`

Returns nearest packaged JMA observation stations with distance.

`GET /api/v1/rainfall/stations/{station_id}/extremes`

Returns packaged/cached ranked events.

`GET /api/v1/rainfall/events/{event_id}`

Returns event metadata and whether an observed temporal profile is available.

## 6.4 Resource estimate

`POST /api/v1/estimate`

Input: area + accuracy mode.

Output:

- full-1m equivalent cell count;
- preliminary adaptive estimate if available;
- estimated memory class;
- estimated disk class;
- runtime class `small|medium|heavy|very_heavy`;
- warnings.

This endpoint MUST NOT present a wall-clock completion-time promise.

## 6.5 Runs

`POST /api/v1/runs`

Creates run and returns:

```json
{
  "run_id": "uuid",
  "status": "QUEUED"
}
```

`GET /api/v1/runs/{run_id}` returns current state snapshot.

`POST /api/v1/runs/{run_id}/cancel` cancels active run.

`GET /api/v1/runs/{run_id}/events` is an SSE endpoint.

SSE event payload SHALL contain:

- monotonically increasing `sequence`;
- run state;
- stage code;
- Japanese stage label;
- optional determinate progress `0..1` only when measurable;
- short message;
- timestamp.

Do not fabricate a percentage for SFINCS runtime when no defensible total-work estimate exists.

## 6.6 Results

`GET /api/v1/runs/{run_id}/result-metadata`

Returns geographic bounds, available time indices, units, max depth summary, grid-level summary, limitations.

`GET /api/v1/runs/{run_id}/layers/max-depth.png?max_px=4096`

`GET /api/v1/runs/{run_id}/layers/depth.png?time_index=N&max_px=4096`

`GET /api/v1/runs/{run_id}/layers/grid-resolution.png?max_px=4096`

PNG layers use transparent pixels for no-data and dry depth below display threshold.

`GET /api/v1/runs/{run_id}/inspect?lon=&lat=&time_index=` returns native-resolution point values.

- Product alignment: yes — API can back both local and future hosted UI.
- Do now: fixed routes and stable errors.
- Do later: tile API if large hosted results require it.
- Permanent non-goal: raw filesystem access through API.

Reuse the merged automatic GSI tile pipeline.

Provider priority is fixed:


- preserve NoData provenance;

- horizontal sample spacing/source class;

- event/ranking date/time metadata;
- rank where available;
- source URL/reference;
- catalog generation date;
- data-quality flags available from source.

## 8.2 Historical uniform mode

```text

simulation rainfall duration = D
```

## 8.3 Observed-profile mode

```text
0 < intensity_mm_per_h <= 500

```

## 8.5 Simulation time

v0.1 simulation start is rainfall start and simulation stop is rainfall end.

No hidden post-rainfall drain-down tail is added in v0.1.

Output interval:

```text
target <= 120 time frames
minimum interval = 60 s
maximum interval = 900 s
interval = round upward to whole minutes where possible
```

```text

```

# 10. Roof rainfall mass conservation

## 10.1 Required behavior

Meteorological rainfall falling on building footprints MUST NOT disappear.

For each connected building footprint:

1. determine footprint area represented in the source 1 m rainfall-allocation grid;
2. set blocked building allocation weight to zero;
3. find eligible non-building perimeter ground cells;
4. distribute the removed rainfall volume across those cells;
5. preserve total rainfall volume within numerical tolerance.

## 10.2 Recipient search

Preferred recipient cells are 8-neighbor ground cells directly adjacent to the building footprint.

If none exist, expand by 1 m Chebyshev rings to maximum distance **5 m**.

If no eligible recipient exists within 5 m, model preparation fails with `ROOF_RUNOFF_NO_RECIPIENT`.

Do not discard the volume.

## 10.3 Distribution

Within one building, distribute by recipient ground-cell area uniformly unless a later specification defines drainage directions.

Source allocation grid output:

```text
rain_weight = 0 inside blocked building
rain_weight = 1 on ordinary ground
rain_weight > 1 on roof-runoff recipient cells
```

Mass condition:

```text
abs(sum(rain_weight * cell_area) - meteorological_domain_area)
/ meteorological_domain_area <= 1e-9
```

for deterministic fixture grids; real projected/rasterized models MUST meet `<= 1e-6` relative error.

## 10.4 SFINCS forcing

Because building cells are blocked, SFINCS precipitation forcing MUST support the spatial redistribution weights.

The model builder SHALL construct spatial precipitation forcing as:

```text
P_hydraulic(x,y,t) = P_meteorological(t) × rain_weight(x,y)
```

This spatial variation is only a roof-runoff allocation correction. The meteorological rainfall assumption remains spatially uniform.

### Chapter check

- Product alignment: yes — mass is conserved without pretending to know roof plumbing.

# 12. Adaptive mode

## 12.1 Core rule

Adaptive is **accuracy-first**.

The implementation starts from high-resolution source information and only permits coarser hydraulic cells where evidence says fine hydraulic resolution has little expected benefit.

Quadtree levels:

```text
1, 2, 4, 8, 16, 32 m
```

Adjacent levels MUST satisfy SFINCS/HydroMT quadtree compatibility. Where a 2:1 balance is required, insert transition cells automatically.

## 12.2 Hard refinement constraints

The following prohibit coarsening beyond the stated level:

- building footprint/intersection: 1 m;
- within 2 m of building footprint: <= 2 m;
- mapped road surface: 1 m;
- within 2 m of mapped road surface: <= 2 m;
- identified narrow channel/major concentrated flow path: <= 2 m;
- user critical region, if added later: not part of v0.1 UI.

## 12.3 Terrain complexity metric

Do not use raw slope magnitude alone, because a smooth mountain slope can be represented coarsely.

For each candidate block, compute from best available terrain samples:

- least-squares plane fit;
- residual RMSE;
- maximum absolute residual;
- local curvature indicator;
- presence of local depressions/ridges that change connectivity;
- flow-accumulation concentration indicator.

Initial configurable coarsening thresholds are **provisional implementation constants** and MUST be validated before Adaptive is recommended:

| Target cell | plane residual RMSE | max abs residual | feature rule |
|---:|---:|---:|---|
| 32 m | <= 0.08 m | <= 0.25 m | no hard feature |
| 16 m | <= 0.06 m | <= 0.20 m | no hard feature |
| 8 m  | <= 0.05 m | <= 0.15 m | no hard feature |
| 4 m  | <= 0.04 m | <= 0.12 m | no hard feature |
| 2 m  | <= 0.03 m | <= 0.10 m | transition / near-feature |
| 1 m  | otherwise | otherwise | required |

A smooth constant slope may satisfy a coarse level even with large total elevation range.

## 12.4 Land-use advisory evidence

OSM polygons tagged as parking, park/recreation ground, or farmland MAY support a coarsening candidate, but MUST NOT override terrain complexity or hard-refinement constraints.

## 15.3 PNG rendering

```text

PREPROCESSING_TERRAIN

BUILDING_GRID

READING_RESULTS
COMPLETE

CANCELLING

```

Rules:

- only coordinator mutates run lifecycle;
- UI does not infer stages from log text;
- state transition table is unit-tested;
- terminal states: COMPLETE, FAILED, CANCELLED;
- failure records failing stage + stable error code + developer detail in log;
- retry creates a new run ID in v0.1; it does not mutate a failed run back to active.

Illegal transition MUST raise internal invariant error and fail the run rather than continue with inconsistent state.
