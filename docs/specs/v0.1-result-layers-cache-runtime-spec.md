# v0.1 RESULT layers, flow vectors, prepared-input cache, and runtime-progress specification

> Status: Active implementation contract for PR #12
>
> Scope: Full 1 m only. Adaptive remains unavailable.

## 1. User-visible goals

This slice fixes seven observed issues:

1. the analysis boundary must be unmistakable on RESULT;
2. time-depth stepping must visibly change the saved time-dependent result;
3. result overlay opacity must be user-adjustable;
4. the computational-grid button must produce an unmistakably different map layer;
5. time-dependent flow direction vectors must be displayable;
6. already acquired/preprocessed map inputs must be reusable for fast reruns when the area/grid are unchanged and only rainfall changes;
7. SFINCS runtime progress/remaining-time display must follow actual engine progress rather than an unrealistic one-second-style estimate.

## 2. Analysis boundary

RESULT SHALL render the exact analysis bounds as:

- red outline `#DC2626`;
- line width >= 3 px;
- above every result/vector raster;
- optional very light red fill <= 0.03 opacity.

The boundary is always visible for all result layers.

## 3. Result overlay image lifecycle

Normalized time-dependent arrays remain the result source of truth.

For each layer/time selection the browser SHALL load the corresponding same-origin result image and replace the MapLibre image source with the newly resolved image. Repeatedly visited URLs SHOULD be cached by the browser/component.

The implementation MUST NOT derive time depth by modifying the maximum-depth PNG.

Time-depth image identity includes the actual backend `time_index`.

Switching among:

- maximum depth;
- time depth;
- grid;
- time indices

must produce a source replacement/repaint, not merely update the button state.

## 4. Opacity control

RESULT SHALL expose:

`解析結果の透明度`

Range:

- 0–100%;
- default 82%;
- affects the primary result raster;
- does not hide the red analysis boundary;
- flow arrows remain readable independently.

## 5. Computational-grid layer

Full 1 m has one resolution category over the active domain, so the layer is expected to be visually uniform by category.

Nevertheless switching to `計算格子` SHALL clearly replace the depth raster with the grid-resolution raster.

Legend SHALL clearly state:

`実計算格子: 1 m`

For future Adaptive results, existing categorical 1/2/4/8/16/32 m semantics remain reserved.

## 6. Flow vector output

### 6.1 Engine output

Newly built Full 1 m SFINCS models SHALL set:

`storevel = 1`

SFINCS NetCDF variables:

- `u(time,n,m)` — x-direction velocity, m/s;
- `v(time,n,m)` — y-direction velocity, m/s.

Both must be present together. One without the other is RESULT_INVALID.

### 6.2 Normalization

Normalized result arrays MAY contain:

- `velocity_u_mps`;
- `velocity_v_mps`.

For active/wet cells, non-finite velocity is invalid.
For dry/inactive cells, product vector velocity is zero/no-data as appropriate.

Existing runs without velocity output remain readable and SHALL expose flow-vector availability = false.

### 6.3 Rendering

Backend exposes a transparent flow-vector PNG aligned to exact result bounds.

Vectors are spatially sampled for legibility; sampling affects visualization only, not stored hydraulic output.

Arrows:

- direction from normalized u/v;
- skip speed below a small display threshold;
- approximately uniform arrow length with optional modest speed scaling;
- transparent background.

RESULT provides a `流れベクトル` toggle.

When enabled:

- vectors overlay the current primary result layer;
- vector time uses the selected actual output `time_index`;
- timeline is visible even if the primary layer is maximum depth/grid;
- old results without velocities show an explicit unavailable message.

## 7. Prepared-input cache

Existing raw provider caches remain unchanged.

Add a higher-level prepared Full 1 m cache keyed by:

- exact analysis-area geometry;
- grid resolution/mode;
- preprocessing schema/revision.

The cache stores rainfall-independent prepared hydraulic inputs:

- terrain array;
- building mask;
- road mask;
- SFINCS mask;
- Manning array;
- roof-rain redistribution weight array and diagnostics;
- grid geometry/CRS;
- provider/provenance summary needed for the run manifest.

Rainfall is NOT part of the key.

Therefore a rerun with the same area/grid but changed rainfall can skip:

- GSI acquisition/reprojection;
- PLATEAU/OSM acquisition/parsing;
- building/road rasterization;
- Manning construction;
- roof-rain allocation;
- Full 1 m grid construction.

Changing area or grid contract produces a cache miss.

The cache must be versioned so a future preprocessing-semantic change can invalidate prior prepared entries.

Result/run directories remain independent; cached prepared data is read-only input to a new run.

## 8. SFINCS real progress and ETA

SFINCS stdout officially emits lines of the form:

`35% complete, ... s remaining`

The local runner SHALL capture these lines while preserving stdout/stderr log files.

The application SHALL use the reported percentage as real solver progress.

For remaining-time UI, do not trust the engine's rough remaining-seconds value by itself. Once progress > 0:

`estimated_total = elapsed / progress_fraction`

`estimated_remaining = max(0, estimated_total - elapsed)`

This estimate is based on actual elapsed wall time and actual SFINCS percentage on this machine/run.

Before reliable progress is available, show indeterminate activity and no precise remaining seconds.

UI during engine execution:

- determinate SFINCS progress when parsed;
- actual percent;
- elapsed time;
- `残り目安` from elapsed/progress;
- label that remaining time is an estimate.

No fabricated progress is allowed.

## 9. API additions

`RunStatusResponse` adds optional:

- `progress_fraction: number | null`;
- `estimated_remaining_seconds: number | null`.

Result metadata adds:

- `flow_vectors_available: boolean`.

New result endpoint:

`GET /api/v1/runs/{run_id}/layers/flow-vectors.png?time_index=<index>`

Existing endpoints remain backward compatible.

## 10. Responsibility boundaries

- `SfincsRunner`: capture/parse process stdout and report real progress only.
- `RunCoordinator`: own run progress state and prepared-cache orchestration.
- `PreparedGridCache`: serialize/deserialize rainfall-independent prepared Full 1 m inputs.
- `SfincsModelBuilder`: request velocity output.
- `output_reader`: validate/read optional u/v.
- `normalize`: persist normalized velocity arrays/availability.
- `results.view`: render raster/vector presentation only.
- `routes_results`: expose result endpoints only.
- `ResultPanel`: own layer/time/opacity/vector controls.
- `ResultMap`: own MapLibre source/layer lifecycle; no numerical classification.

## 11. Required deterministic tests

Backend:

- model config contains `storevel = 1`;
- output reader accepts paired u/v and rejects one-sided/malformed velocity;
- old result without u/v remains valid;
- normalization persists velocity arrays and metadata flag;
- two time indices produce different time-depth PNG bytes for synthetic changing data;
- flow-vector PNG is non-empty/transparent where no flow;
- prepared cache round trip preserves arrays/diagnostics;
- second same-area run skips provider/grid builder while changed rainfall still reaches model build;
- changed area misses cache;
- progress parser accepts SFINCS progress lines;
- coordinator exposes actual progress + elapsed/progress ETA.

Frontend:

- opacity slider changes ResultMap opacity prop;
- time button/slider changes exact image URL;
- grid button changes exact image URL/label;
- vector toggle uses exact selected time index;
- vector unavailable state is visible;
- ResultMap boundary contract is red and overlay source replacement is exercised at source level where practical.

## 12. Host acceptance

One fresh Full 1 m Windows run SHALL confirm:

- red boundary visible;
- time-depth changes across at least two non-identical wet time steps;
- opacity slider visibly changes overlay;
- grid layer visibly replaces depth;
- flow arrows render and change with time where flow exists;
- repeat same-area run with changed rainfall reports prepared-cache hit and visibly skips acquisition/preprocessing quickly;
- SFINCS progress percentage advances;
- elapsed time advances;
- displayed remaining-time estimate is of the correct order of magnitude and is updated from actual progress;
- RESULT remains functional.

Keep PR Draft/Open/unmerged. Adaptive remains disabled.
