## Why this is next

The Full 1 m calculation path is `local-review-ready`, including a fresh Windows run through SFINCS, result reading and normalization.

The remaining v0.1 end-to-end product flow explicitly requires result visualization:

```text
Read results
-> Display flood depth on map
-> Inspect maximum depth / time evolution / point values
```

Product requirements `RES-001..006` and implementation-spec sections 6.6 and 15 define the result contract.

## Implementation order

### Slice A — backend result viewing contract

Implement the fixed result API:

- `GET /api/v1/runs/{run_id}/result-metadata`
- `GET /api/v1/runs/{run_id}/layers/max-depth.png?max_px=`
- `GET /api/v1/runs/{run_id}/layers/depth.png?time_index=&max_px=`
- `GET /api/v1/runs/{run_id}/layers/grid-resolution.png?max_px=`
- `GET /api/v1/runs/{run_id}/inspect?lon=&lat=&time_index=`

Rules:

- normalized arrays are the source, not raw UI filesystem access;
- display depth below 0.01 m is transparent;
- no-data is transparent and remains distinct from zero;
- point inspection samples native normalized arrays, never the display PNG;
- point outside result returns `POINT_OUTSIDE_RESULT`;
- no-data inspection succeeds with `has_data=false`;
- PNG rendering is deterministic and bounded to max 4096 px;
- grid-resolution resampling is nearest-neighbor;
- result metadata includes limitations plus actual provider/engine summary.

### Slice B — Full 1 m result map UI

Replace the smoke-only completion state with a result view backed by the fixed API:

- MapLibre GL JS 6.x;
- GSI standard raster base map with required attribution;
- maximum-depth layer by default;
- exact depth-band labels from the UI implementation specification;
- analysis-area outline;
- metres in legend;
- limitations remain visible;
- actual provider fallback / engine metadata visible;
- no official-warning implication.

### Slice C — time depth and point inspection

- actual output time indices only;
- no interpolation;
- native point inspection;
- no-data distinct from zero.

### Slice D — grid-resolution layer and acceptance

- Full 1 m displays the 1 m resolution layer;
- Adaptive remains disabled until its separate canonical acceptance gate;
- deterministic frontend/API tests;
- final Windows local UI/SFINCS smoke is host-local Codex work only after Web-owned CI is green.
