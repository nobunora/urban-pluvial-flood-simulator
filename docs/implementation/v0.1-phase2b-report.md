## Current implemented boundary

- `floodsim/providers/geocoder.py` uses only the approved CSIS Simple Geocoding endpoint, shared network/retry policy, defensive XML parsing, WGS84 validation, candidate ordering, and a ten-candidate cap.
- `floodsim/api/routes_geocode.py` exposes `GET /api/v1/geocode` with trimmed/bounded input, CSIS attribution metadata, and stable 400/503 errors.
- `floodsim/providers/jma.py` parses official AMeDAS station data and explicit JMA rainfall ranking labels for 10-minute, 1-hour, and daily events.
- JMA ranking parsing is limited to the ten ranked value columns. The trailing statistics-period column is explicitly excluded and cannot become a false rank-11 event.
- `data/jma/stations.json` contains 1,286 precipitation-capable stations.
- `data/jma/rainfall_extremes.json` contains 60 deterministic events from the two packaged official ranking snapshots: 2 stations × 3 supported durations × 10 ranks.
- Every packaged event contains station longitude/latitude and runtime loading verifies station ID, name, and coordinates against `stations.json`.
- Nearest-station search follows the canonical API contract and searches all packaged precipitation-capable stations. A station may legitimately have an empty `extremes` list when no event snapshot is packaged for that station.
- Runtime loading validates schema version, rank bounds, event metadata type, profile consistency, and station/event identity/coordinate consistency.
- `scripts/build_jma_rainfall_catalog.py` preserves every recognized top-ten event in the supplied ranking snapshots and no longer applies the previous rank-two/station-duration selection.
- The JMA maintenance generator rejects non-`jma.go.jp` HTTPS provenance/source URLs, including lookalike hosts, credential-bearing URLs, non-standard HTTPS ports, and non-HTTPS URLs. Programmatic `build_catalog()` calls are subject to the same official-source restriction.
- Each ranking source used to build a catalog must provide recognized 10-minute, 1-hour, and daily rainfall rows. If any required duration is absent, generation fails explicitly rather than publishing a silently partial catalog.
- `tests/test_phase2b_generator_contracts.py` independently locks the official-source and required-duration generator contracts.
- `RainfallEventResponse` exposes `station_lon_deg`, `station_lat_deg`, and `event_date_or_datetime_metadata: str | null` rather than an unconstrained type.
- `web/openapi.json` and `web/src/api/generated.ts` are the committed generated API contracts.
- `web/scripts/api-types.mjs --check` normalizes CRLF/LF before comparison so platform-only EOL differences do not create false drift failures; substantive generated-contract differences still fail.
- `.gitattributes` pins generated API artifacts and `floodsim/static/**` to LF to make Windows/POSIX checkout and Vite-build behavior deterministic.
