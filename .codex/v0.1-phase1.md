## FastAPI contract

```text
/api/v1
```

Phase 1 exposes only one real feature endpoint:

```text
GET /api/v1/health
```

Do not create fake success endpoints for geocoding, rainfall, runs, estimates, results, or providers.

The health response must be a typed Pydantic response and contain at least:

```json
{
  "status": "ok",
  "api_version": "v1",
  "application_version": "<version>",
  "engine": {
    "required": "SFINCS 2.4.0 Galibier"

}
```

The endpoint must not search for or launch SFINCS in Phase 1.

Normal API exceptions must not expose Python tracebacks or local filesystem paths.

## Domain contracts

Use Pydantic v2 for API-visible and persisted Phase 1 contracts.

### LonLat

Fields:

```text
lon_deg: float
lat_deg: float
```

Validation:

```text
-180 <= lon_deg <= 180
-90 <= lat_deg <= 90
```

Do not use unlabeled numeric coordinate tuples across module boundaries.

### GeoBounds

Fields:

```text
west_deg
south_deg
east_deg
north_deg
```

Validation:

```text
west_deg < east_deg
south_deg < north_deg
```

### ProjectedBounds

Fields:

```text
xmin_m
ymin_m
xmax_m
ymax_m
crs
```

Validate numeric ordering. CRS must be explicit, not inferred.

### AnalysisArea

Fields:

```text
mode: preset_square | rectangle
bounds
center
width_m
height_m
area_m2
```

Allowed preset half sizes:

```text
250
500
1000
2000
```

Do not add other public preset sizes.

### AccuracyMode

Exact values only:

```text
full_1m
adaptive
```

Reject any other value.

## Run state machine

Use the exact states:

```text
CREATED
VALIDATING
ACQUIRING_TERRAIN
ACQUIRING_VECTORS
ACQUIRING_RAINFALL
PREPROCESSING_TERRAIN
ALLOCATING_ROOF_RAIN
BUILDING_GRID
BUILDING_MODEL
ENSURING_ENGINE
RUNNING_ENGINE
READING_RESULTS
COMPLETE
FAILED
CANCELLING
CANCELLED
```

Normal progression:

```text
CREATED
→ VALIDATING
→ ACQUIRING_TERRAIN
→ ACQUIRING_VECTORS
→ ACQUIRING_RAINFALL
→ PREPROCESSING_TERRAIN
→ ALLOCATING_ROOF_RAIN
→ BUILDING_GRID
→ BUILDING_MODEL
→ ENSURING_ENGINE
→ RUNNING_ENGINE
→ READING_RESULTS
→ COMPLETE
```

Failure transition:

- every non-terminal active processing state may transition to `FAILED`.

Cancellation transition:

- cancellation-eligible active states may transition to `CANCELLING`;
- `CANCELLING` may transition to `CANCELLED`;
- do not invent resume/retry transitions in v0.1.

Terminal states:

```text
COMPLETE
FAILED
CANCELLED
```

No transition is allowed out of a terminal state.

Illegal transitions must raise an explicit internal invariant error. They must not be silently ignored or coerced.

Unit tests must cover every legal transition class, representative illegal transitions, and terminal-state protection.

Do not implement the run coordinator or background worker in Phase 1.

## Stop conditions

Return `spec-change-required` and stop without starting Phase 2 if any of these occurs:

- FastAPI/React/Vite materially conflicts with current repository constraints;
- Pydantic v2 cannot coexist with the validated Phase 0 environment;
- Phase 0 would need to be invalidated or rewritten to make Phase 1 work;
- a required domain/API contract contradicts the canonical specification;
- completing the skeleton would require implementing Phase 2+ functionality;
- a new external-service contract decision is required;
- an approved dependency cannot be obtained from a legitimate source.

SFINCS executable redistribution/bootstrap licensing is not a Phase 1 stop condition because Phase 1 must not implement distribution or bootstrap.

Do not silently substitute architecture, dependency families, or product behavior.
