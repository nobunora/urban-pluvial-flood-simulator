## Objective

Close the only remaining Phase 0 blocker by executing the existing deterministic fixture with a **user-supplied, legitimately obtained SFINCS v2.4.0 Galibier executable**.

Do not start Phase 1 until this pass reaches `validated`.

## User prerequisite

The user obtains/installs SFINCS v2.4.0 Galibier outside this repository.

Before running this task, the user SHALL expose the absolute executable path through environment variable:

```text
SFINCS_EXE=<absolute path to sfincs.exe>
```

PowerShell example:

```powershell
$env:SFINCS_EXE = 'C:\path\to\sfincs.exe'
```

The path above is an example only. Do not guess or hard-code a user path.

If `SFINCS_EXE` is absent, empty, or does not point to a file, stop with:

```text
Disposition: user-action-required
Reason: SFINCS_EXE is not a valid local executable path.
No production change made: yes
```

Do not download SFINCS, automate login, scrape the Deltares portal, install Docker, or substitute another binary.

## Required procedure

### Step 1 — verify user-supplied executable

In PowerShell:

```powershell
if (-not $env:SFINCS_EXE) { throw 'SFINCS_EXE is not set' }
if (-not (Test-Path -LiteralPath $env:SFINCS_EXE -PathType Leaf)) { throw 'SFINCS_EXE does not point to a file' }
Get-Item -LiteralPath $env:SFINCS_EXE | Select-Object FullName,Length,LastWriteTimeUtc
Get-FileHash -Algorithm SHA256 -LiteralPath $env:SFINCS_EXE
```

Record the absolute path only in local validation output; do **not** commit a user-specific filesystem path to permanent documentation. The committed Phase 0 report records the SHA-256 and acquisition class `user-supplied permitted local executable`.

### Step 2 — create/use the pinned Python 3.12 environment

Reuse the Phase 0 environment when it still matches `environment.yml` and the report.

Verify:

```powershell
python --version
python -c "import hydromt_sfincs, hydromt; import importlib.metadata as m; print(m.version('hydromt_sfincs')); print(m.version('hydromt'))"
```

Required values:

```text
Python 3.12.x
hydromt_sfincs 2.0.0rc3
hydromt 1.4.1
```

If the environment differs, recreate the pinned Phase 0 environment. Do not edit the dependency pins merely to use an existing environment.

### Step 3 — run existing focused tests before engine execution

Run:

```powershell
python -m pytest -q tests/test_sfincs_phase0.py
```

All tests that do not require a local engine MUST pass. An engine-dependent skip caused solely by the harness not being passed an executable is acceptable before Step 4.

### Step 4 — execute the real engine through the existing harness

Use a temporary/generated output directory that is ignored by Git:

```powershell
python scripts/sfincs_phase0_spike.py `
  --out-dir artifacts/phase0b `
  --sfincs-exe $env:SFINCS_EXE `
  | Tee-Object -FilePath artifacts/phase0b-result.json
```

The harness must execute the regular zero-rain fixture generated by the pinned HydroMT-SFINCS integration.

Do not manually edit the generated `sfincs.inp`, grid files, NetCDF files, or result file to make the run pass.

### Step 5 — verify execution result

Required evidence:

- SFINCS process reaches normal completion;
- process return code is `0`;
- harness execution status is `pass`;
- `sfincs_map.nc` was produced by this execution;
- direct Xarray reader succeeds on this execution-produced file;
- required result variables/dimensions remain compatible with the Phase 0 report;
- zero-rain fixture satisfies the existing reader zero-water invariant;
- no NaN/Inf condition causes the reader to fail;
- SHA-256 of the executable is recorded;
- captured SFINCS stdout/stderr identifies the engine as v2.4.0 Galibier, or another reliable local version artifact supplied with the executable does so.

**Do not infer the SFINCS version solely from the executable filename.**

If engine output does not expose a trustworthy version identity, stop with `user-action-required` and state exactly what version evidence the user must provide. Do not weaken the version requirement.

### Step 6 — rerun tests after proof

Run:

```powershell
python -m pytest -q tests/test_sfincs_phase0.py
python -m pytest -q
```

Do not claim tests that were skipped or not executed.

## Stop conditions

### `user-action-required`

Use this disposition and make no product change when:

- `SFINCS_EXE` is missing/invalid;
- executable version cannot be reliably established;
- the supplied executable cannot run because of missing user-machine runtime prerequisites unrelated to generated model compatibility.

Report the exact user action required.

### `spec-change-required`

Use this disposition and stop when the genuine v2.4.0 Galibier engine proves a material compatibility problem, including:

- generated model is rejected without unapproved semantic/manual rewrite;
- execution succeeds but required result quantities cannot be read deterministically;
- actual output schema materially contradicts the canonical implementation specification;
- passing would require changing SFINCS/HydroMT-SFINCS versions or hydraulic meaning.

Do not begin Phase 1 in this disposition.

### `validated`

Use only when:

```text
Regular build: PASS
Quadtree build: PASS
Subgrid build: PASS
SFINCS execution: PASS
Execution-produced result read: PASS
```

At that point Phase 0 is complete and the next PR may begin Phase 1.
