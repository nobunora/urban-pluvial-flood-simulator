Implement **Phase 2A only**: move the existing GSI / PLATEAU / OSM acquisition capability behind application-owned provider modules without changing its hydraulic meaning.

Phase 2 is deliberately split into two bounded PRs:

```text
Phase 2A  geographic providers: GSI / PLATEAU / OSM
Phase 2B  CSIS geocoder + packaged JMA rainfall catalog/APIs
```

Phase 3 MUST NOT begin until both Phase 2A and Phase 2B are validated.

The Phase 2A result must establish this dependency direction:

```text

            │
            ▼
      floodsim/providers/*
            │
            ▼

```

The application/provider layer MUST NOT import executable CLI entrypoints from `scripts/`.

## 3. Current repository facts that MUST be preserved

The implementation must start from the actual merged behavior, not recreate it from memory.

### GSI

Current source is `scripts/download_gsi_dem.py`.

Required existing invariants:

```text
fallback order:
DEM1A -> DEM5A -> DEM5B -> DEM5C -> DEM10B

GSI elevation RGB decode:
x = 2^16 R + 2^8 G + B
x < 2^23  -> x * 0.01 m
x = 2^23  -> NoData
x > 2^23  -> (x - 2^24) * 0.01 m
```

Do not change signed decoding, source priority, NoData meaning, source-count provenance, or nearest-fill diagnostics.

### PLATEAU

Current source is `scripts/download_plateau_vectors.py`.

Required existing invariants:

- PLATEAU is the first-choice vector provider.
- request feature types `bldg,tran`;
- preserve EPSG:6697 / Japanese CityGML axis handling already proven by tests;
- building preference remains:

```text
lod0FootPrint
-> lod0RoofEdge
-> GroundSurface
-> generic polygon fallback
```

- road polygons are preferred when present; line geometry remains allowed when polygon surface is unavailable.

### OSM

Current source is `scripts/download_osm_vectors.py`.

Required existing invariants:

- OSM is fallback, not first choice;
- building and highway geometry only for the current v0.1 provider path;
- provider fallback must be disclosed in returned provenance;
- do not present OSM completeness as equivalent to PLATEAU.

### Current CLI behavior

The following existing callable/CLI behavior is compatibility surface and MUST continue to work:

- `scripts.download_gsi_dem.download_dem(...)`
- `scripts.download_plateau_vectors.download_plateau_vectors(...)`
- `scripts.download_osm_vectors.download_osm_vectors(...)`

Do not rename or remove those entrypoints in Phase 2A.

## 5. Provider dependency rule

Production provider code lives under `floodsim/providers/`.

After extraction:

```text
floodsim/providers/* MUST NOT import scripts.*
```

Existing `scripts/download_*.py` MAY import and delegate to `floodsim.providers.*` to preserve CLI compatibility.

Shared parser/acquisition logic must have one authoritative implementation. Do not leave two independent GSI decoders, two PLATEAU parsers, or two OSM parsers that can drift.

Do not move `scripts/prepare_inputs.py` or hydraulic rasterization into the provider package in Phase 2A.

## 6. Application-facing area contract

Provider application APIs MUST accept the Phase 1 `AnalysisArea` contract, not only `center_lat + center_lon + half_size_m`.

This is mandatory because v0.1 supports both preset squares and arbitrary rectangles.

Use:

```text
AnalysisArea
- mode
- bounds: GeoBounds (EPSG:4326)
- center: LonLat
- width_m
- height_m
- area_m2
```

Do not invent unlabeled `(lat, lon)` tuples across provider boundaries.

### Local projected frame

Where a metric local frame is required by existing extraction/reprojection logic, use WGS84 AEQD centered at `AnalysisArea.center`.

For a rectangular area:

```text
xmin = -width_m / 2
xmax = +width_m / 2
ymin = -height_m / 2
ymax = +height_m / 2
```

Any acquisition margin MUST be explicit and recorded separately from the requested analysis area. A margin must never silently change `AnalysisArea` itself.

Antimeridian-crossing areas are not supported by the existing `GeoBounds` contract (`west_deg < east_deg`). Do not add antimeridian support in Phase 2A.

## 7. Common network policy

Create an explicit named network policy in `floodsim/providers/common.py`.

Reference defaults from the canonical spec:

```text
connect timeout: 10 s
read timeout:    60 s
max attempts:     3
backoff:          1 s, 2 s
retryable status: 429, 500, 502, 503, 504
```

Requirements:

- constants live in one place;
- provider sessions use the shared user agent;
- tests must not actually sleep during retry tests;
- do not scatter scalar `timeout=30`, `timeout=90`, or similar literals through production provider code;
- if a provider demonstrably requires a different read timeout, define a named provider-specific policy and explain it in the Phase 2A report instead of hiding the override.

Expected user agent:

```text
urban-pluvial-flood-simulator/0.1
```

No authentication secrets are introduced in Phase 2A.

## 8. Common provider errors

Create explicit internal provider exception classes sufficient to distinguish expected source failures from programming defects.

Minimum categories:

```text
ProviderError
ProviderUnavailableError
ProviderRequestError
ProviderParseError
ProviderCoverageError
```

Provider code must wrap expected HTTP/source/parse failures into these categories while preserving the original exception as cause.

Do NOT catch `Exception` around an entire provider implementation and reinterpret programming errors as source unavailability.

Public API error mapping is not part of Phase 2A; these are internal contracts for later orchestration.

## 9. Provenance contract

Every successful provider acquisition MUST return structured provenance in addition to writing any compatibility artifact.

Create a strict model or dataclass with at least:

```text
provider_id
provider_name
requested_bounds
acquired_at_utc
attribution
terms_url
warnings[]
source_details
```

`source_details` may be provider-specific but must be JSON-serializable and deterministic in tests.

Do not include machine-specific absolute paths in provenance intended for manifests.

Fallback is a warning/provenance event, not an invisible implementation detail.

## 10. GSI provider contract

Create an application provider in `floodsim/providers/gsi_elevation.py`.

Required public responsibility:

```text
acquire elevation for AnalysisArea at requested target grid spacing
-> write/return the same normalized elevation product needed by later terrain processing
-> return GSI provenance/source counts
```

Exact function/class naming is allowed to follow repository style, but the provider boundary must be typed and covered by tests.

### Rectangular output

Unlike the old square-only CLI implementation, application-facing acquisition MUST support rectangular `AnalysisArea`.

For target spacing `grid_m`:

```text
nx = round(width_m  / grid_m) + 1
ny = round(height_m / grid_m) + 1
```

The normalized array orientation and x/y vectors must be documented and tested.

Do not transpose/flip silently. Preserve the existing solver-compatible y orientation unless a deliberate, tested application contract replaces it.

### Source provenance

Retain at least:

```text
provider counts by DEM class
nearest filled cell count
missing fraction before nearest fill
requested grid spacing
elevation source names
GSI attribution
GSI terms reference
```

`grid_m = 1` MUST mean hydraulic/normalized grid sampling request, not a claim that source terrain accuracy is 1 m.

### Coverage failure

If fallback sources still leave more than the approved nearest-fill threshold missing, raise a typed `ProviderCoverageError`.

Do not convert unknown elevation to zero.

## 13. Vector fallback orchestration

Implement one application-owned vector acquisition function/service with exact modes:

```text
auto
plateau
osm
```

Behavior:

### `plateau`

- try PLATEAU only;
- no OSM fallback;
- expected PLATEAU provider failure propagates as typed failure.

### `osm`

- use OSM only.

### `auto`

1. try PLATEAU first;
2. on an expected `ProviderError` representing upstream availability/request/parse/coverage failure, record a fallback warning;
3. try OSM;
4. if OSM succeeds, returned provenance MUST say that OSM fallback occurred and preserve the PLATEAU failure category/message in developer diagnostics;
5. if both fail, raise one typed acquisition failure preserving both causes/details.

Do NOT fallback on unrelated `AssertionError`, `TypeError`, `NameError`, invariant violation, or arbitrary programming exception.

This narrows the current `except Exception` behavior intentionally to avoid hiding defects while preserving the product's PLATEAU -> OSM fallback policy.

## 14. Cache rules

Preserve source cache reuse.

Phase 2A cache requirements:

- GSI cache key contains layer/zoom/x/y;
- PLATEAU cache key is deterministic from source URL/source identity;
- OSM cache key includes request area identity sufficiently precisely to avoid cross-area collisions;
- cached bytes are reparsed/validated before being trusted where practical;
- cache paths remain implementation details and are not exposed in normal API/provenance output;
- no database is added.

Do not implement the final processed-cache/version invalidation system from Phase 3+ in this PR.

## 21. Stop conditions

Stop with disposition `spec-change-required` instead of guessing if any occurs:

- preserving existing CLI behavior requires a breaking public API change;
- the current GSI source contract materially contradicts the canonical fallback/decode rules;
- the current PLATEAU source contract no longer supports the required CityGML acquisition path;
- supporting rectangles would require changing `AnalysisArea` semantics;
- provider integration requires hydraulic/numerical policy changes;
- OSM fallback licensing/attribution cannot be represented without a product-level decision;
- the only way to make tests pass is to hide provider failures or silently change provenance;
- Phase 2A cannot be completed without implementing geocoder/JMA/Phase 3 behavior.

Do not silently replace GSI, PLATEAU, or OSM with another service.
